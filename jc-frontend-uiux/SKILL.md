# JC Frontend UI/UX 设计纪律

核心命题：**你说不出名字的缺陷，就修不掉。** 「看着不舒服」不可证伪、不可定位、不可交接；把它翻译成「A 和 B 的〔属性〕差得太〔大/小〕，导致〔具体观感〕」，修法会自动浮现。对 AI 而言这句话加倍成立：需求词汇越模糊，输出上限越低。

本 skill 的全部价值 = 一套指认问题的词汇 + 一个不许跳步的流程。

## 强制流程（三阶段，不许跳步）

### 阶段 1：设计预算声明（写代码前）

先写出三张预算表，写不出就不许开工：

1. **信息清单**：列出页面每个元素，按铁律 1 的两问分类为「信息 / 意符 / 噪音」。噪音不该出生；意符声明它以什么形态存在（常驻 / 弱呈现 / hover 浮现 / 收进详情）。
2. **层次预算**：声明本页允许几种区域底色（≤2：导航 / 工作）、几条结构线（目标 0–1 条）、用什么手段分层。
3. **颜色预算**：声明页面色相族（基准强调色的 OKLCH 色相）、允许哪些离族色、各自担任什么语义职务（状态 / 警告 / AI 标识）、出现在多大面积。

### 阶段 2：生成

在预算内生成。预算外的新增元素、线条、颜色，必须先回到阶段 1 修订预算并说明理由。

### 阶段 3：自查 + 量化回验（交付前）

逐项跑 `references/checklist.md` 的三组清单（冗余 / 层次 / 颜色），每项给出「删除 / 替换 / 保留」，不允许沉默地「通过」。凡涉及颜色与对比度的判断，运行 `scripts/color_audit.py` 拿数值：

```bash
python3 scripts/color_audit.py oklch "#5D42D6"                 # L/C/H
python3 scripts/color_audit.py contrast "#E6DFD7" "#FCFBF9"    # 对比度 + 区间判定
python3 scripts/color_audit.py family "#D64200" "#5D42D6"      # 相对基准色的色相距与色度比
```

改完必须重新量化或实测，数值回到目标区间才算完成；「我看着好多了」不是验证。

## 三条铁律（词汇的骨架）

1. **冗余与意符分开（防过度精简）**。精简删掉的是噪音，永远不能删的是意符（signifier）——用户靠它判断「这是什么、能点吗、点了会怎样」。两问测试：
   - 一问：它承载信息或操作入口吗？否 → 噪音，候选删除。是 → 进入二问。
   - 二问：删掉后，第一次见到的用户 5 秒内还能说出「我在哪 / 这是什么 / 我能干嘛」吗？能 → 删除；不能 → **弱化，不删除**：可降对比、降尺寸、延迟到 hover 出现、收进详情，但意符必须存在。
   - 渐进披露三层：核心功能常驻可见；次要功能弱呈现；高级功能收进详情/菜单，但入口必须可发现。
   - 删「功能」与删「线索」不同：整个功能不要了，连带界面一起删是安全的；只删入口线索而功能还在，是事故。
2. **层次手段优先级**：留白 > 字重/灰阶 > 底色差 > 描边。描边是最后手段，不许用描边补底色差的不足。区域底色 ≤2 级，卡片/浮层用材质色 + 阴影，同底色区域之间不划线。
3. **色相族纪律**：小面积强调色必须属于页面色相族；离族色只有在担任语义职务时才允许存在，且面积小、出现短暂。交互反馈色（hover/press/focus）走标准 Token（focus-ring / 品牌色），不许随手借语义色。

## 理论锚点（词汇的来源）

- **意符与示能**（Don Norman《设计心理学》）：好设计最重要的两个特性是可发现性与反馈；意符可以做轻，但物理上必须存在。Windows 8 / 早期 iOS 扁平化翻车 = 把意符和装饰一起铲掉。
- **自明性测试**（Steve Krug《Don't Make Me Think》）：self-evident 与 self-explanatory 的分界——删掉某元素后用户需要「想一下」才能回答基本问题，它就不是冗余。
- **极简与识别的对冲**（Nielsen 十大启发式 #8 vs #6）：#8 说每个无关信息单元都在和相关信息竞争注意力；#6 说识别优于回忆，操作线索要可见。删「无关」，留「识别」。
- **消除附加工作与渐进披露**（Alan Cooper《About Face》）：精简的对象是不服务用户目标的 excise，不是理解所需的线索；功能按使用频率分层披露，而非删除。
- **扁平化实证**（Nielsen Norman Group, Kate Moran 2017）：纯扁平、弱意符界面使用户导航任务耗时增加约 22%，因为可点击性不确定。「过度精简」有实锤的失败案例。

## 诊断区间速查

| 感受 | 量化判据 |
| --- | --- |
| 虚（线条发虚） | 线条对比 1.2–1.4 |
| 肉 / 糊（面不分） | 相邻面对比 <1.1 |
| 脏 | 低明度（L<0.6）+ 高色度（C>0.15）用作大面积底色 |
| 突兀（颜色跳） | 色相距（圆环）>150° 且色度 ≥ 主强调色；90–150° = 离族，需语义职务 |
| 可读性 | 文字 ≥4.5:1；大文字与非文字控件 ≥3:1 |

## 诊断他人/已有界面「不舒服」时（显影四步）

1. **记录原话**：「有点脏 / 怪 / 不舒服」原样写下，不许当场改写——它是待翻译的输入。
2. **定位到元素**：截图 → 放大 → 追到具体元素及其 Token/数值。注意问题可能藏在交互态（hover/press/focus），静止截图里看到的线可能是 hover 染色的。
3. **量化三属性**：对比度、OKLCH（L/C/H）、面积；用显影句式改写原话。
4. **修复并回验**：改完重新量化，回到目标区间。
