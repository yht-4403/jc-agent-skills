# JC Learning Map

## 中心任务

把用户暂时看不清的主题整理成一张能定位、能继续展开的地图：

```text
这件事在解决什么
→ 主流程或核心模块
→ 一级卡点：通常卡在哪类问题
→ 二级卡点：这类问题的常见具体情况
→ 第一步预案：先看什么、先做什么
```

先给全貌，再定位当前入口。全图默认画到两层卡点；只有当前卡点继续深挖。

默认使用“总览模式”：每个主节点只展示一个最具代表性的一级卡点和最多两个二级情况。这个数量是首次交付的版面限制，不代表领域中只存在这些问题。用户明确要求完整卡点手册时再扩充。

## 首次使用契约

当前对话第一次使用时，用一小段话说明：本 Skill 不会把主题扩写成百科，而会先交付一张可扫读的全貌图，用两层卡点帮助用户认出当前位置，并给出当前最值得先学或验证的一步。材料齐全时说明后立即画图，不等待确认；主题缺失时只询问想梳理的主题和用途。证据不足时可以先给候选入口，但不得伪装成确定判断。当前对话后续不重复这段介绍。

## 边界与转交

- 用户只想弄清一个词的含义、用法和边界时，转给 `dbs-deconstruct` 或直接解释，不生成领域地图。
- 用户明确要一次性深度长文、行业内幕、案例和场景模拟时，转给 `domain-sprint`。
- 用户想连续学习一个课题（地图先行、逐讲深入、应用导向）时，转给 `jc-learning`；用户明确要求按反馈逐篇推进的慢节奏课程时，才转给 `dbs-learning`。
- 用户提供十万字级书籍、课程或知识库，并要求做成长期领域 Skills 时，转给 `domain-skill-factory`；需要持续批处理时再使用 `domain-skill-loop`。
- 用户只要求解决眼前的 SQL、代码、销售或沟通问题，没有看全貌或建立地图的意图时，直接使用相应领域能力。

显式调用本 Skill 时尊重用户选择，但仍要说明资料范围和能力边界。

## 默认工作过程

### 1. 确认地图服务什么目标

识别用户输入属于概念、具体问题、任务、能力还是领域。说明用户希望看懂、执行、排查还是长期学习。

已有信息足够时直接开始。只有范围差异会明显改变地图时，才提出一个简短问题。

### 2. 说明结果怎样产生

先用大白话说明：

- 这件事主要解决什么；
- 什么结果代表做成了；
- 用户当前为什么需要这张地图。

不要从术语目录或资料章节开始。

### 3. 选择合适的地图形态

- 有明显前后阶段：使用流程图。
- 需要定位故障或原因层级：使用问题地图。
- 多种能力共同决定结果：使用能力图。
- 同时包含阶段、能力和诊断：使用混合地图。

无法判断或主题跨多种形态时，读取 [地图形态与输出示例](references/map-patterns.md)。

### 4. 建立主地图和两层卡点

主地图只保留会改变结果的关键节点。对每个关键节点给出：

1. 节点目标或正常输出；
2. 最具代表性的一级卡点：卡在哪类问题；
3. 最多两个容易识别的二级情况；
4. 第二层对应的第一步预案。

“完整”表示关键阶段没有明显缺口，不表示穷举所有边缘情况。合并低价值分支，不为结构对称强行补节点。

总图是索引，不是教学正文。一级卡点、二级卡点和预案默认使用短语或一句短动作；其他常见分支不在首次总图逐项列出，把解释留给当前入口。

### 5. 定位当前入口

结合用户材料和问题，指出：

- 当前最可能位于哪个节点和二级卡点；
- 这个判断依据是什么；
- 现在最值得先弄懂或验证什么；
- 哪些部分暂时可以忽略。

证据不足时给少量候选入口和区分方式，不伪装成确定判断。

### 6. 只深挖当前卡点

用户选择或确认某个二级卡点后，再继续补充原因、区分信号、判断方法、行动和边界。无关分支保持两层，不展开整棵树。

当开始深挖的当前卡点属于技术或系统机制，并且存在可核对的代码、接口输入输出、日志或截图时，默认转入 `../plain-explainer/SKILL.md`，并读取其 `references/artifact-first-understanding.md`，不等待用户主动要求“小白体感”。地图继续承担索引作用；仍处于总览阶段时不要提前加载，也不要用一张更大的图替代原始制品和实际过程。

实践出现新情况时，把经过验证的卡点或预案补回地图；没有真实证据的分支标记为候选，不写成通用规律。

## 资料使用

按以下优先级工作：

1. 用户指定的原始资料和真实案例；
2. 与主题匹配的当前权威资料；
3. 稳定常识，用于形成待校准的地图草案。

使用指定资料时：

- 说明实际读取范围；
- 区分来源观点与 Agent 的结构归纳；
- 不把目录改写成知识地图；
- 不宣称未处理内容已经覆盖。

主题具有明显时效性时，按当前环境规则核对最新来源。资料庞大且用户要求完整覆盖或长期 Skill 时，停止轻量整理并转交领域 Skill 工厂。

## 交付契约

首次地图通常包含：

1. 一句话说明；
2. 全貌图；
3. 关键节点；
4. 每个节点的两层卡点和第一步预案；
5. 用户当前入口；
6. 建议先学或先验证的一小块；
7. 依据、未知和适用边界；
8. 可继续展开的少量方向。

首次交付默认使用可快速扫读的紧凑版：每个主节点只展示一个一级卡点和最多两个二级情况，总图保持简短，当前入口可以详细。用户明确要求完整手册时再扩充。用户提供真实案例时优先完成定位。格式服从主题，不强制每次填写同一张表。

## 核心 Gotchas

- 不把“搞懂”自动解释成生成一篇大而全长文。
- 不把整本书的章节目录当成领域结构。
- 不默认展开第三层及更多分支。
- 不把两层卡点写成逐项讲解的巨大表格；总图必须能快速扫读。
- 不在总览模式为一个主节点罗列多个一级卡点；其余内容等当前节点确认后再展开。
- 不为了显得完整而编造卡点、潜规则、比例或阈值。
- 不把一次性经验、用户偏好或来源作者观点写成普遍事实。
- 不把知识地图、学习课程、概念定义和长期 Skill 工程混成同一产物。
- 不因资料很多就假装已经全量处理。

## 停止条件

出现以下情况时暂停地图生成，并说明最小下一步：

- 主题含义不同会产生完全不同地图，且现有信息无法判断；
- 用户要求完整覆盖大型资料，但尚未进入领域资料工厂；
- 缺少关键资料会使高风险或时效性判断不可靠；
- 现有相邻 Skill 更符合用户明确目标；
- 当前问题已经可以直接解决，继续画全图只会增加负担。
