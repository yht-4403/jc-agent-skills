# 地图形态与输出示例

当主题无法直接套用一种地图、需要控制两层卡点的粒度，或需要参考输出形态时读取。

## 核心概念

- **主地图**：说明结果怎样产生，或能力和问题由哪些关键部分组成。
- **一级卡点**：某个节点通常会卡在哪一类问题。
- **二级卡点**：这类问题中可被用户识别的常见具体情况。
- **第一步预案**：遇到二级卡点后，先观察什么或采取什么动作。

两层卡点是一项产品设计规则，用于兼顾全貌和可用性，不是所有领域天然存在的客观层级。来源不足时保留为候选结构。

## 选择地图形态

### 流程图

适合销售、供应商筛选、需求验证、海外市场验证等有明显推进阶段的任务。

```text
找到对象 → 建立接触 → 理解问题 → 提出方案 → 验证结果
```

流程节点应代表结果发生必须经过的重要环节，不照抄课程章节。

### 问题地图

适合 Bug 排查、SQL 优化、系统性能、内容无流量等诊断主题。

```text
确认现象 → 收集证据 → 定位层级 → 验证原因 → 修复与回归
```

一级卡点通常是故障类别，二级卡点是可观察的具体情况。

### 能力图

适合沟通、写作、销售能力、管理和关系等由多种能力共同决定的主题。

```text
理解情境 / 获取信息 / 形成判断 / 表达与行动 / 根据反馈调整
```

能力之间不一定线性流动，应说明依赖和共同作用，避免伪造唯一学习顺序。

### 混合地图

复杂主题可以用流程展示全貌，再把关键能力或问题挂到对应节点。只保留对定位有帮助的关系。

## 两层卡点示例

以 Bug 排查中的“复现”为例：

```text
复现
├── 无法稳定复现（一级卡点）
│   ├── 本地无法复现（二级卡点）→ 先核对版本、环境和初始状态
│   ├── 只能偶发复现（二级卡点）→ 先自动重复并记录时间线
│   └── 只在线上复现（二级卡点）→ 先补线上观测和失败证据
└── 观测改变执行（一级卡点）
    └── 打开断点后问题消失（二级卡点）→ 改用非阻塞日志或追踪
```

全图到这里停止。只有用户确认“本地无法复现”后，才继续拆环境、状态、数据、时序或外部依赖。

## 简洁输出骨架

总图只承担定位，不承担逐项教学。默认每个主节点只展示一个一级卡点和最多两个二级情况，卡点和预案优先写成短语；当前入口再解释依据和动作。

```markdown
# {主题}地图

## 一句话说明

## 全貌

## 关键节点

### {节点}
- 目标或正常输出：
- 一级卡点：
  - 二级卡点 → 第一步预案

## 你当前可能在哪

## 建议先学或先验证什么

## 依据与边界

## 下一步可以继续拆
```

骨架用于提醒，不要求每次机械填写。简单主题可以合并栏目，真实问题优先给定位结果。

## 深度控制

- 全图默认到两层卡点。
- 总览模式下，每个主节点只展示一个一级卡点和最多两个二级情况。
- 当前二级卡点允许继续深入。
- 无关节点不补第三层原因。
- 分支只保留能帮助识别或决定下一步的内容。
- 一个节点分支过多时合并相近项，不用大表格穷举。
- 新卡点优先来自真实材料、案例和失败记录。

停止继续拆解的标准：

> 当前问题已经能通过可观察信号进行区分，并能对应一个明确的下一步行动。
