# jc-learning：地图先行的工具箱学习法

## Overview

把一门学问拆成 8-12 个可直接使用的「思维工具」，先生成全景学习地图，再按用户节奏逐讲深入。每讲固定三段式：概念机制 → 原典/出处带读 → 应用场景与练习。实用性是结构的三分之一，节奏完全归用户——可跳学、可不写反馈直接继续。

与 dbs-learning 的区别：dbs-learning 按学科体系逐篇推进、每篇等待用户反馈；本方法地图先行、应用优先、反馈可选。用户明确表达「太慢」「学完不知道怎么用」时，使用本方法。

## 触发信号

- 用户想系统学习一个主题，且在意速度和实用性
- 用户说「继续」「下一讲」「继续学 XX」（已有课题）
- 用户嫌现有学习 skill 节奏慢或脱离实际
- 用户想继续「投资与Web3」「哈耶克与米塞斯」等已用本模式建立的课题

## 核心设计决策

1. **地图先行**：任何内容生成之前，先给全景——8-12 个思维工具一张表，用户始终知道自己在哪、还剩什么
2. **工具化拆解**：不按学科章节切，按「能拿来干什么」切。每个工具绑定一类真实问题
3. **三段式结构**：概念机制、原典带读、应用练习。三者缺一不可
4. **节奏归用户**：用户说「继续」就直接写下一讲，不要求先填反馈；用户点名跳学就直接跳
5. **沉淀回路**：练习答案写回讲次文章末尾，精炼后同步学习地图的进度表

## 工作流程

### 新课题

1. **确认课题名**。
2. **轻量检索已有知识**：用 Grep 在知识库中搜索课题相关关键词，识别用户已有的相关笔记（已理论化的观点、未理论化的实践直觉都算）。检索到足够概括知识基础即停，不遍历。跳过敏感文件。
3. **生成学习地图**（见下方模板）。工具清单中每个工具给出：核心一句话、应用场景（优先绑定用户当前在做的项目）、原典/出处、状态。
4. **生成第 01 讲**（见下方模板），选择用户提到过的或最能立即应用的工具。
5. 两份文件一次性交付。

### 继续已有课题

1. 读取课题学习地图，确认进度表和各讲状态。
2. 检查最新一讲末尾的「学习反馈与应用沉淀」区：有用户填写内容则提取并据此调整下一讲；没有则在下一讲开头注明「本篇基于当前可见上下文生成」，直接推进。
3. 用户点名跳学时直接写点名的工具，跳过顺序。
4. 生成后更新学习地图：工具状态、进度记录表（讲次、主题、日期、练习情况、新理解摘要）。

### 沉淀

- 用户在讲次文章末尾写下的练习答案、新理解、疑问，在当轮结束前精炼后写入文章，并同步学习地图进度记录。
- 不保存逐字聊天记录，不为一次闲聊建新文件。
- 事实性内容（原著出版年份、历史事件、引文）标注核对日期。

## 文件存放规则

遵循当前项目自身的文档规则。在 JC 知识库中：

- 存放于 `02-日常思考/`
- 学习地图命名：`YYYY-MM-DD-{课题名}学习地图.md`
- 讲次命名：`YYYY-MM-DD-{课题名}-第XX讲-{主题}.md`，序号用中文数字两位（第 01 讲）
- 不新建分类目录，不打 type/主题标签

其他项目：优先遵守该项目 AGENTS.md 或 README 中的文档规则；无规则时询问用户。

## 学习方式

{三段式说明 + 节奏规则}

```markdown

## 这一讲要解决的问题

{1-3 句话，把抽象主题落到一个真实问题上。}

## 概念机制

{把概念讲清楚，用因果句说明机制。必要时做二级拆解。}

> {原文关键段落}

## 应用题

{3 道题：第一道解剖用户自己的真实决策，第二道找外部案例套用框架，第三道反向自检。}

## 小结

{3-5 条。}

## 下一讲预告

---

## 学习反馈与应用沉淀

（练习答案、新的理解、想展开的问题写在这里，会精炼后同步到学习地图）

待填写。
```

## 写作原则

- 永远使用中文；中英文之间、中文与数字之间加空格；中文标点用全角。
- 呈现差异，不用纠错姿态。禁用句式：不是……而是……／不在于……在于……／不需要……需要……／真正的……是……／与其说……不如说……。用因果句、条件句、动作句替代。
- 像懂行的朋友在讲解，不写教科书腔调。
- 应用场景必须具体：绑定用户当前项目（默认优先当前主项目、管理与协作、日常社会观察），不写空泛的「这个理论可以应用到很多领域」。
- 应用题必须可操作：能在 10 分钟内动手做，且至少一道题直接解剖用户自己的真实决策。

## 验收用例

### 用例 1：新课题

用户说「带我系统学博弈论」。

必须：

- Grep 检索知识库中博弈论相关内容，概括已有知识基础
- 生成学习地图（8-12 个工具，每个绑定应用场景和出处）
- 生成第 01 讲
- 两份文件按项目文档规则存放

### 用例 2：继续课题，无反馈

用户说「继续」。

必须：

- 读学习地图确认进度
- 检查上一讲反馈区，无内容则在开头注明「本篇基于当前可见上下文生成」
- 生成下一讲并更新地图进度

### 用例 3：跳学

用户说「先学第 06 讲企业家精神」。

必须：

- 直接生成第 06 讲，不要求补前面的讲次
- 更新地图中该工具的状态和进度记录

### 用例 4：反馈驱动调整

用户在某讲末尾写「概念看懂了，但案例跟我的场景太远」。

必须：

- 提取该反馈
- 下一讲换案例来源，贴近用户当前项目
- 在进度记录的「新的理解摘要」中记录本次调整
