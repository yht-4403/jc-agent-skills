## 工具与权限

优先使用当前环境中已配置的飞书连接器或 `lark-cli`。执行前读取与当前 CLI 版本匹配的 `lark-doc`、`lark-whiteboard` 和认证规则；不要把本文件当作完整 API 手册。

用户要求创建或更新时才写入。用户身份缺少权限时按最小 Scope 发起授权，并同时提供原始授权链接和二维码；用户完成后由 Agent 继续验证。用户拒绝授权时交付本地 XML 或 Markdown 源稿。

## 原生组件映射

在飞书文档 XML 中通常使用：

- 高亮：`callout`；
- 分栏：`grid`＋`column`；
- 文字强调：`b`、`span text-color`、`span background-color`；
- 待办：`checkbox`；
- 分隔线：`hr`；
- 画板：`whiteboard`；
- 普通结构：`p`、标题、列表和表格。

标签、转义、属性和颜色以当前 CLI 内置 Skill 为准。用户点名富排版时可以提高组件密度，但仍按内容语义选择，不机械堆叠。

## 原生画板

飞书文档可通过 `whiteboard type="mermaid"`、`plantuml`、`svg` 或空白画板创建可继续编辑的画板。创建后保存返回的画板 Token，并通过画板查询能力验证代码、SVG、预览图或原生节点结构。

Mermaid 或 SVG 转为画板节点后，具体可编辑程度取决于解析结果。不要仅凭创建成功就声称每个元素都可编辑；至少反向查询一次。

## 跨端流程

普通线性流程仍优先使用文档原生纵向高亮块＋`↓`。只有连接关系本身重要，或用户明确需要在画板里拖拽编辑时，才创建画板。

两栏、三栏适合短对比；四个以上阶段不做横向箭头链。飞书文档中的箭头和标题应使用文本元素，不依赖仅桌面可见的定位。

## 校验

- 创建后读取文档并提取新增 Block；
- 画板必须返回非空 Token；
- 需要证明可编辑时，查询代码或原生节点结构；
- 导出预览图进行视觉检查；
- 检查空白画板、重复标题、错序、超宽图和权限提示；
- CLI 返回更新提示时，在完成当前任务后告知用户，不静默升级。
