# 云文档协作与版本规范

在更新既有文档、多人协作、同一任务包含多个受众、需要设置权限，或存在多个旧版本时读取。

## 写入前确认

先确认四件事：

1. 目标平台和账号；
2. 精确文档 ID、链接或目标文件夹；
3. 本次是创建、定点更新、重排还是审查；
4. 谁可以看、谁可以编辑，以及文档是否含候选人、客户、薪资或内部信息。

同时连接个人版和企业版时必须让用户选择目标账号。只凭标题搜索到多个同名文档时，不猜测目标。

## 读取后再写

- 更新前读取文档结构和相关正文；长文分页读到末尾。
- 识别用户手工新增、删除或改写的内容，不拿本地旧稿覆盖在线新内容。
- 小改动优先查找并定点更新 Block、段落或组件；只有结构整体失效或用户明确要求重建时才创建新文档。
- 用户未要求处理的评论、修订、附件、权限和无关章节保持不变。
- 不自动接受全部修订，不自动解决或删除评论。

## 受众隔离

不同受众需要物理分开的文档时，先确定每份文档的唯一用途：

- 外发文档只保留该受众应该看到的事实、结论和行动；
- 私密文档可以包含准备话术、风险、薪资底线和个人提醒；
- 私密文档可以链接外发文档，外发文档不得反向暴露私密链接；
- 真实人才资料对外发布前脱敏，不把简历、手机号、邮箱或评估记录复制到公开文档。

## 版本与标题

- 活动文档使用稳定标题，不累计“最终版、终版2、最新版、手机版”。
- 资料截止日期、更新时间和覆盖范围写进正文或元数据，不靠标题版本号表达。
- 同一内容的小改动更新活动文档；重大结构变化才考虑新建替代品。
- 新版反向验证完成前，旧版保持可用。
- 需要保留历史时移入明确的归档位置；不需要时，在用户授权范围内移入回收站并说明可恢复性。

存在多个旧版本时，先给出精确标题、ID、时间和处理建议。不要按模糊关键词批量删除，也不要处理用户未放入范围的文件。

## 权限

- 默认沿用现有权限；新文档默认选择满足任务的最小权限。
- “所有人可编辑”风险高于“所有人可查看”，只有用户明确要求时设置。
- 分享给面试官、客户或公众前检查文档中是否含私密内容和私密反向链接。
- 设置后重新查询或读取权限状态，不能只信任写入成功响应。
- 权限能力不支持精细成员控制时，说明限制，不把全员权限冒充定向分享。

## 冲突与并发

无法确定在线内容是否在本轮被其他人修改时，重新读取目标范围再写。发现用户改动与本地稿冲突时：

- 保留用户在线修改；
- 只合并本次明确新增的内容；
- 会改变含义的冲突停止并列出差异，不静默选择一边。

不要同时对同一文档发起相互依赖的多个写操作。需要批量编辑时先确认定位结果，再按平台支持的原子或可回滚方式执行。

## 发布后验收

至少检查：

- 开头、目录或导航、关键章节、图片/图示、来源和结尾都存在；
- 标题层级、列表、分栏、箭头和手机端顺序没有异常；
- 没有 Unsupported、空组件、占位符、字面 Markdown 标记、断链或丢图；
- 权限、账号和文档所有者符合预期；
- 外发与私密内容没有串线；
- 交付链接指向活动版本。

最后返回文档标题、链接、主要受众、权限、更新时间、已处理旧版本和仍待确认项。没有完成反向读取时，不声明发布完成。
