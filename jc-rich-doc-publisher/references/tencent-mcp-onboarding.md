# 腾讯文档 MCP 小白接入

仅在以下情况读取：用户主动询问腾讯文档 MCP 配置；当前没有腾讯文档工具；工具返回鉴权失败。已经可正常调用时不要让用户重复配置。

## 目标体验

尽量把用户的手动操作压缩为：打开腾讯官方页面、登录并获取 Token。其余配置与验证由 Agent 完成，但前提是当前宿主提供安全凭据输入和 MCP 配置能力。Skill 不能把“有操作说明”假装成“任何客户端都能自动安装”。

## 先检测

1. 查看当前工具列表是否存在腾讯文档官方 MCP 能力；工具名与参数以实时 Schema 为准。
2. 若存在只读用户信息或身份查询能力，先调用一次。
3. 查询成功即视为已经连接，不输出配置教程，不索取 Token。
4. 工具存在但返回鉴权错误时，进入重新授权；只有写权限不足时，不要求用户重配整个 MCP。

## 官方入口与标准配置

腾讯文档官方 Token 页面：

```text
https://docs.qq.com/open/auth/mcp.html
```

腾讯文档官方 MCP 地址：

```text
https://docs.qq.com/openapi/mcp
```

腾讯文档团队当前公开的通用配置结构为：

```json
{
  "mcpServers": {
    "tencent-docs": {
      "url": "https://docs.qq.com/openapi/mcp",
      "headers": {
        "Authorization": "你的Token值"
      }
    }
  }
}
```

请求头名称必须是 `Authorization`。不要自行改成 `token`、`auth`、`X-Token`，也不要在 Token 前擅自增加 `Bearer `；若官方页面后续改变，以当时官方说明为准。

官方使用指南：

```text
https://developer.cloud.tencent.com/mcp/server/11803
```

## 交给 AI 的安全边界

“把 Token 交给 AI”只能指以下方式之一：

- 宿主提供专门的 Secret、密码或凭据输入框；
- 宿主允许 Agent 调用受控的 MCP 配置工具，真实值不会出现在聊天、日志和最终回答；
- 用户自己把 Token 粘贴到可信客户端的 MCP 设置页或本机配置中。

普通聊天没有安全凭据入口时：

- 不要求用户把 Token 发在对话正文；
- 不把真实 Token 放进 shell 命令、截图、文档、Skill、Git、示例或诊断输出；
- 只给出官方页面、MCP 地址和带占位符的配置，让用户在客户端设置中完成一次粘贴；
- 客户端只支持明文配置文件时，提醒它属于本机敏感配置，不提交版本库、不转发，并按客户端能力限制本地文件访问。

若用户已经把 Token 发在普通聊天、公开文档或仓库中，停止复述，建议回到官方页面重新生成或重置后再连接。

## 配置后的验证

1. 重新发现腾讯文档工具，不能只看配置保存成功。
2. 调用只读用户信息能力，向用户显示昵称或账号类型等非敏感识别信息，请其确认是否为目标账号。
3. 同时连接个人版和企业版时，在第一次写入前让用户选择本次目标账号；当前对话保持该选择，用户明确切换时再改变。
4. 用户已经要求创建或更新文档时，验证完成后继续原任务，不让用户重新描述正文。
5. 用户只是要求配置时，到只读验证成功为止，不擅自创建测试文档。

## 常见错误

| 信号 | 处理 |
| --- | --- |
| 找不到腾讯文档工具 | 检查 MCP 是否已添加、启用并重新加载；不先判断 Token 错误 |
| `400006` 或鉴权失败 | 检查 `Authorization` 名称、Token 是否完整、账号是否正确；必要时重新获取 |
| `400007` 或能力不足 | 按官方说明检查账号权益；不要用重复配置掩盖权限问题 |
| 只读成功、写入失败 | 检查目标文档权限、目标账号和工具写权限，不重新索取 Token |
| 用户有多个账号 | 显示可识别账号信息并让用户选择，不猜测 |
| 官方页面与当前工具名不同 | 以当前 `tools/list`/Schema 为执行依据，以官方页面为授权入口 |

## 无法连接时的回退

用户拒绝授权、宿主不支持自定义 MCP 或连接持续失败时，交付可继续发布的 MDX/Markdown、Mermaid 和 SVG 源稿，并明确“尚未写入腾讯文档”。不要把本地文件链接冒充在线文档链接。
