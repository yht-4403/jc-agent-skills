# 完整工作流

## 1. 确认用途和资料边界

说明主要使用者、典型任务、资料范围和发布边界。目标不必写成复杂契约，但要足以决定该保留哪些知识、怎样组织地图和用什么任务测试。

## 2. 登记和检查来源

区分原文、二次整理稿和外部研究；检查重复、缺章、扫描页、图表、时效和许可。保留原始文件，不在预处理时改写它。

## 3. 切块并建立状态

按章节和语义边界生成可定位文本块。记录 pending、in_progress、extracted、reviewed 和 skipped，让长任务可以分批恢复。

## 4. 先做地图草案

根据真实任务、目录、样本章节和案例，画出领域的大体结构。地图用于指导后续检索，不必一开始就定稿。参照 [知识地图方法](knowledge-map.md)，选择流程、能力树、问题地图或混合结构。

## 5. 贯通少量样本

选几个有代表性的文本块，尝试完成原子、方法归纳、Reference、执行 Skill 和真实测试。样本阶段主要发现：原子是不是太碎，地图是不是抄目录，Skill 有没有真正掌握方法。

## 6. 分批抽取与持续归纳

逐批阅读原文、写原子、处理重复与冲突，并不断修正地图。注意寻找作者反复使用的底层判断、典型案例和失败边界，而不只是增加知识条数。

## 7. 划分 Skill 与 References

用共同方法论和用户任务划分 Skills。重要方法、场景、案例库和模板放进 References；SKILL.md 保留中心任务、底层框架、工作方式和引用入口。

多 Skill 套件建立主路由。路由表使用用户的真实表达和问题，不使用原子字段做界面。

## 8. 测试与发布

先运行结构和引用校验，再用陌生案例做独立前向测试。发现误路由、理论复述、过度确定或无法完成产物时，回到方法论和案例，而不是只补字段。

## 9. 增量维护

新资料按哈希进入，只重算受影响的原子、地图和 References。真实使用中的失败案例优先进入测试或案例库。

## 阶段门

- 来源混乱时，不扩大抽取；
- 样本不能回指原文时，不进入批量；
- 地图仍只是章节摘要时，不开始大规模生成 Skills；
- 执行 Skill 只会讲理论时，不发布；
- 代表任务没有通过时，不宣称完整可用。

脚本把长任务变得可恢复、可审计。领域理解、方法提炼和 Skill 写作仍由 Agent 完成。
