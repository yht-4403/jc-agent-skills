# B2B商机复盘与跟进

把客户会议纪要、聊天记录或销售笔记转化为可执行的商机推进方案，减少销售人员会后整理、写跟进、补CRM和准备下一次沟通的时间。

## 适用场景

当用户出现以下需求时启用：

- 复盘客户拜访、需求访谈、方案沟通、演示、报价或谈判会议；
- 从会议纪要或聊天记录中提取客户需求、决策人、预算、时间和风险；
- 判断商机阶段、完整度、下一步动作或丢单风险；
- 生成客户跟进邮件、企微/微信消息、下一次会议议程；
- 整理可复制到CRM的商机更新摘要；
- 提到“商机复盘”“客户跟进”“销售会议”“推进成交”“CRM更新”。

## 核心原则

1. 只依据用户提供的沟通记录与明确背景，不虚构客户承诺、预算、决策人或成交概率。
2. 区分“客户原话”“销售判断”和“待验证假设”。
3. 先判断商机事实，再生成话术；不使用夸大、操纵、施压或虚假稀缺策略。
4. 下一步必须具体到责任人、动作、时间和成功标准。
5. 任何外发消息、CRM写入或会议邀请都只生成草稿；未经用户确认不得代表用户发送或修改外部系统。
6. 涉及客户个人信息、报价、合同和商业秘密时，提醒最小化披露与权限控制。

## 所需输入

优先从用户材料中提取：

- 客户名称或代称、行业与规模；
- 本次沟通类型和日期；
- 参会人及角色；
- 会议纪要、逐字稿、聊天记录或销售笔记；
- 我方产品、方案和本次沟通目标；
- 已知商机阶段、预计金额、计划成交时间（如有）。

缺少核心沟通记录时，先请用户粘贴或上传。信息不全但可以分析时，继续执行并明确标记缺口。

## 工作流程

### 第一步：提取沟通事实

按以下结构整理，不加入记录中不存在的事实：

- 客户目标与期望结果；
- 当前做法、痛点及其业务影响；
- 明确需求和隐含需求；
- 已讨论的方案、范围、价格或条件；
- 客户提出的问题、异议和顾虑；
- 客户、我方各自作出的承诺；
- 已确定的时间点与下一步。

关键事实尽量附上客户原话或原文依据；短引用即可，不复制无关长段落。

### 第二步：评估商机六要素

读取 @references/opportunity-rubric.md。

对以下六项分别判断“明确、部分明确、缺失”：

1. 业务目标与痛点；
2. 决策角色与影响关系；
3. 决策标准与流程；
4. 预算条件与采购限制；
5. 时间计划与紧迫事件；
6. 竞争方案与双方承诺。

每项给出证据、缺口、风险和需要追问的问题，不用一个总分制造虚假确定性。

### 第三步：判断阶段与风险

基于证据判断当前更接近：

- 初步接触；
- 需求确认；
- 方案匹配；
- 商务评估；
- 决策审批；
- 成交或暂停。

给出阶段判断依据和置信度。若销售标注阶段与证据不一致，要明确指出。

风险至少覆盖：

- 价值未量化；
- 关键角色缺席；
- 决策流程不清；
- 没有客户承诺的下一步；
- 价格先于价值讨论；
- 竞争对手或维持现状；
- 时间表由我方单方面设定；
- 需求、权限或交付边界存在误解。

### 第四步：设计推进动作

优先给出1—3个最关键动作。每个动作包含：

- 目的；
- 负责人；
- 截止时间；
- 所需材料；
- 客户需要作出的可验证承诺；
- 成功与停止条件。

避免把“继续保持联系”“推进项目”当作有效动作。

### 第五步：生成跟进材料

读取 @references/output-templates.md，按用户需要生成：

- 客户跟进邮件；
- 企微/微信短消息；
- 下一次会议议程；
- CRM更新摘要；
- 内部协同任务清单。

跟进材料应简洁、具体、方便客户确认，不擅自增加折扣、承诺、交付范围或截止日期。

### 第六步：交付复盘

默认按以下顺序输出：

1. 一句话商机判断；
2. 本次沟通关键事实；
3. 商机六要素；
4. 风险与缺口；
5. 下一步行动；
6. 客户跟进草稿；
7. CRM更新摘要；
8. 下一次会议议程。

## 质量检查

交付前确认：

- 是否把客户原话、销售判断和假设分开；
- 是否漏掉双方承诺、责任人或时间点；
- 阶段判断是否有证据；
- 跟进消息是否包含清晰的确认事项；
- 下一步是否能在日历或任务系统中落地；
- 是否避免未经授权的报价、承诺和外部发送。

## 表达方式

- 使用销售团队易于执行的简洁语言。
- 结论先行，重要风险放在前面。
- 原始记录很长时，先给管理摘要，再给证据明细。
- 用户只需要一项产物时，直接生成该产物，不强制输出整套报告。
