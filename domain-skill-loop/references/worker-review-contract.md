# Worker 与 Reviewer 契约

## Worker 输入

- 当前 batch_id 与 chunk_id 列表；
- 对应文本块及必要相邻上下文；
- 工厂的 extraction-protocol 和 schemas；
- 已有原子索引，用于查重与冲突登记。

## Worker 输出

- 新增或修正的原子；
- 本批每个块的处理说明；
- 发现的重复、冲突、图片/OCR、低置信度和越界项；
- 不得自行写 reviewed。

## Reviewer 输入

- 原始文本块；
- 本批新增/修改的原子；
- 来源注册表与数据契约；
- 不读取 Worker 的“我认为已经完成”等自评。

## Reviewer 检查

1. 忠实度：陈述是否被短引支持，是否扩大范围或因果。
2. 完整性：块内重要原则、动作、案例、反例、边界是否漏抽。
3. 粒度：是否一条一义，条件与结论是否错误拆开。
4. 类型与关系：类型、阶段、场景候选、冲突是否合理。
5. 安全边界：是否把时点经验、违法/违规动作或模型推断写成通用规则。

## Pass 条件

- 机械校验通过；
- 没有高严重度忠实度错误；
- 重要知识漏抽率可接受；
- 所有低置信度与冲突项明确登记；
- Reviewer 身份不同于 Worker。

## Fail 输出

Reviewer 必须给出可执行返工项：涉及的 chunk_id/atom_id、错误类别、证据和期望修正。禁止只写“质量不好”。
