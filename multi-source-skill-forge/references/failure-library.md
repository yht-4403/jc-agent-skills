# 失败模式库

按阶段归档的"踩过的坑"。**新发现的失败模式请追加到这里** —— 这份库是 skill 本身的进化机制。

---

## 阶 0 · 定盘

| 失败 | 症状 | 修法 |
|---|---|---|
| **画像没问** | 拆出一堆漂亮但没人调用的能力 | 三个问题不能省；画像四个字段不能是"普通人" |
| **入口数没问** | 交付时才发现用户想要的是 1 个入口，而产出是 12 个独立 skill | 阶 0 就问，且要在阶 3 用预算复核 |
| **多源主题不同** | 来源数量够，但两两之间没有共同问题 | 拆成两个独立项目。**"多源"的前提是同主题**，否则三角矩阵是空的 |
| **凭记忆开工** | 没有源文本就开始拆 | 停下来要材料。宁可等也不编 |
| **tertiary 来源当一手** | 拿 AI 转写稿/聚合站的结论做核心主张 | tertiary 单独不能支撑任何能力卡 |

## 阶 1 · 通读

| 失败 | 症状 | 修法 |
|---|---|---|
| **跳过批判段** | skill 把作者偏见当真理打包出去 | 批判段少于 3 条不得进阶 2。这是硬门 |
| **写的是读后感** | 骨架是"我觉得作者想说的是…" | 自检："我在复述作者，还是在表达自己" |
| **术语用字典义** | 作者的特定概念被当日常词用 | 词典必须写"作者本人的用法" |
| **多源没做来源对照** | 各来源分别通读，最后才第一次见面 | 阶 1 第 1 步就要回答"它们共同在回答哪个问题、各自从什么角度切入" |

---

## 阶 2 · 抽丝

| 失败 | 症状 | 修法 |
|---|---|---|
| **5 路串成 1 路** | 一个 extractor 顺手把别的路也做了 | 每跑一路前明确"现在只执行这一路的职责" |
| **互相污染** | 后一路受了前一路结论影响 | 独立性是阶 3 的前提，被污染则"独立佐证"是假的 |
| **检索式伤覆盖率** | 用了检索式，漏掉了散落的关键单元 | 覆盖率硬门：相对全量基线漏检数必须为 0，否则退回全量扫描 |
| **提前筛选** | 本阶就把"看起来没用"的删了 | 宁错杀。筛选是阶 3 的职责，本阶删了就没法审计 |
| **长材料丢锚点** | 分块后每块单独读，读出局部理解 | 每块都必须附带 OVERVIEW |

## 阶 3 · 三角（最容易出错的一阶）

| 失败 | 症状 | 修法 |
|---|---|---|
| **V1 作弊（换词重述）** | 同一案例换个说法算两处 | 要求：不同出处 + 不同对象 + 不同结论 |
| **★ 转引当独立** | A 来源其实在引用 B，被算作两条独立证据 | 检查是否有明确引用关系或措辞高度雷同；转引合并为同一证据，`independent: false` |
| **V2 作弊（伪新场景）** | 用一个其实材料里讨论过的类似问题冒充"新问题" | 新场景应该让人第一眼不知道材料里会怎么说 |
| **V3 过松（措辞判断）** | 只要"说得比较文雅"就不算常识 | 看**内容**本身是否反直觉，不看措辞 |
| **画像误删** | 因为用户当前没提到某方向就直接删除 | 正确做法是 `archived for profile`，保留审计与可恢复性 |
| **证据空心化** | 只写"第 3 章有提到" | 必须给短证据 + 为什么独立/为什么有用 |
| **★ 只做跨域，漏做跨源** | 多源材料被当成单源处理，每条结论只标一个出处 | 来源 ≥2 时，三角矩阵是**必做项**，不是可选项 |
| **★ 有分歧但没写争议卡** | 两条来源对同一问题的边界不同，被"综合考虑"糊过去 | 分歧必须固化成争议卡。不允许平均 |
| **★ 置信度不落地** | verified 里写了 A/B/C，卡里却统一用"应该/必须"的语气 | 写完卡回查一遍 `confidence` 字段与语气是否匹配 |
| **预算失控** | 入口数一路涨 | 晋级门硬约束：`1 + promoted ≤ budget`，超了降为能力卡 |

## 阶 4 · 立卡

| 失败 | 症状 | 修法 |
|---|---|---|
| **I 段抄书** | 写成了书摘 | 用"没读过原文的人能否看懂"自检 |
| **A2 太宽** | "用户需要思考时" | 必须给可识别的语言信号，中英双写 |
| **A2 太窄** | 只有一种措辞能触发 | 场景 3–5 条，覆盖不同说话方式 |
| **E 段只有哲学** | "保持客观"当步骤 | 换成"列出 3 个最不希望发生的结果" |
| **缺 B 段** | 卡被过度调用 | 无 B 段的卡不得进阶 5 |
| **跳过 A1** | 卡失去"作者亲自用过"的权威性 | 速成档可省，但必须在 STATE 注明 |
| **标题含"和/与/以及"** | 一句话塞两件事 | 拆卡，或把其中一件降为另一件的 example |
| **卡里带 frontmatter** | 元数据出现在两处，改一处忘一处 | 正文只放六段；元数据只在 bundle |

## 阶 5 · 织网

| 失败 | 症状 | 修法 |
|---|---|---|
| **硬造关系** | 为了"看起来成体系"给每张卡都连一遍 | 10 张卡 8–15 条关系。多于 25 条就是在凑 |
| **术语不对齐** | 同一概念在不同来源里叫法不同，卡之间互相看不懂 | 多源项目必须做别名对齐，写进 GLOSSARY |
| **A2 没回填** | 阶 4 的"与相邻卡的区别"初稿留在卡里 | 阶 5 必须回填定稿，并同步 bundle 的 description |

---

## 阶 6 · 试炼

| 失败 | 症状 | 修法 |
|---|---|---|
| **没有诱饵** | 全部用例都是正例，100% 通过 | 无诱饵用例一律打回 |
| **只测"完全无关"** | 诱饵都是天气查询之类 | 至少 1 条必须是"该触发兄弟能力"的混淆题 |
| **没做边界反转** | B 段写了反场景，但没人验证它守不守得住 | 至少 1 条把反场景包装成正面请求 |
| **盲测泄漏** | 评测者看到了 expected_behavior | 只给卡内容和 prompt；不给 type/notes/通过标准 |
| **修测试而非修卡** | 失败后不断放宽用例 | 每次修测试都必须写理由。警惕自我合理化 |
| **低置信度没被测** | C 级内容在卡里被说得像跨源共识，却没人验 | 多源项目必须加 1 条 C 级话题的用例 |

---

## 阶 7 · 出炉

| 失败 | 症状 | 修法 |
|---|---|---|
| **hub 与 split 同时装** | 同一意图双触发 | 二选一，明确告知用户 |
| **hub 路由表漏行** | 某些能力从 hub 里"失联" | 编译自检：每个 active 能力恰好一个去向 |
| **未测产物被安装** | 把没通过试炼的卡也装进去了 | 只装通过阶 6 的产物 |
| **装完不验** | 装完就当成功 | 抽 1–2 个入口实测能否加载并触发 |
| **DIGEST 只报喜** | 没有陷阱/局限两节 | 两节是必填。否则是软文不是蒸馏 |
| **多源 DIGEST 缺"一致与分歧"节** | 读者看不到三角矩阵的结论 | 多源项目必填 |
| **只交付文件不交付调用路径** | 用户拿到一堆文件但不知道怎么用 | 收尾汇报必须写清安装位置与调用方式 |

## 增量更新专用

| 失败 | 症状 | 修法 |
|---|---|---|
| **静默覆盖** | 新来源与旧结论矛盾，直接改掉了 | 矛盾类必须人工确认，产出或更新争议卡 |
| **形态漂移** | 新增材料后自动从 hub 变成 split | 重新编译默认沿用上次形态，改形态要显式请求 |
| **全量重跑** | 每次新增都从头拆一遍 | 只跑增量（阶 1–2）+ 受影响的卡（阶 4），再整体重跑阶 6 |
| **无快照** | 改坏了无法回滚 | 编译前保留旧产物快照 |
| **未授权采集** | 偷偷上报调用数据来指导演进 | 任何情况下都不得在用户不知情时上报使用数据 |
