# 5 路提取器 — 完整 prompt 定义

阶 2 的执行规范。**每一路都必须独立判断**，不得受其他几路结论影响 —— 否则阶 3 的"独立佐证"就是假的。

调用每一路时，给它的上下文固定为三样：
1. `OVERVIEW.md`（全局锚点，判断"这段在全文中扮演什么角色"）
2. 源文本（或分块 + 块 id）
3. 本文件中的对应 extractor prompt

**不要给**它其他 extractor 的结果。

---

## 通用规则（每一路都要遵守）

- **只做收集，不做筛选。** 宁错杀，交给阶 3。担心被淘汰是阶 3 的事，不是本阶的事。
- **每条候选必须有原文出处**：`source_id` + `source_chapter`（视频填时间戳/分 P，播客填集数）。
- **引用 ≤150 字**（英文 ≤100 词）。
- **边界模糊时宁可多提取**，跨职责的候选照样交，阶 3 会去重。
- **不做跨单元链接**（那是阶 5）。
- 提交前自问三句：这条在原文里有明确根据吗（还是我脑补）？它属于我这路的职责吗？它是不是别的路也会提到的（重复没关系）？

---

## 1. framework-extractor — 思维模型 / 决策框架 / 推理方法

**职责范围**
- **思维模型**：可迁移的思考结构
- **决策框架**：面对决策时的结构化流程
- **推理方法**：从已知推向未知的特定路径

**不属于你**（交给对应 extractor）：原则/清单/规则 → principle；作者亲自用过的案例 → case；失败模式/警告 → counter-example；术语定义 → glossary。

**识别信号**
- 作者给某个思考方式**起了专门的名字**
- 出现 **"面对 X 类问题时应该…"** 的通用流程
- 同一思考结构被**反复在不同章节引用**
- 作者明说"这是我常用的 mental model / 方法"
- 有结构化的 **if-then / 先-后 / 从-到** 句式

**产出格式**
```yaml
- id: f01
  title: 逆向思维
  type: framework
  source_id: src-a
  source_chapter: 第 3 讲
  source_quote: |
    "反过来想，总是反过来想。如果知道我会在哪里死去，那我就永远不去那里。"
  summary: |
    面对目标时，不直接问"怎么达成"，而先问"什么会让我失败"。
    列出失败因素后避开它们，反向推出该做的事。
    这比正向推理更稳，因为人对"不想要什么"的判断通常比"想要什么"更清晰。
  tags: [decision, mental-model, inversion]
```

**数量预期**：方法论密集材料 10–30 个候选。少于 5 很可能漏读了；多于 50 可能把"非框架"也算进来了。

**上下文策略**：**全量扫描**。框架常跨章节隐性分布，需要全局视野。

## 2. principle-extractor — 原则 / 清单 / 规则 / 断言

**职责范围**
- **原则**：作者明确提出的"应该/不应该如何"
- **清单**：结构化的项目列表（检查清单、决策前自问清单）
- **规则**：可直接套用的判断规则（"永远不要…当…" / "只有在…时才…"）
- **格言**：作者反复强调、带行动指导意义的短句

**识别信号**：`必须…` / `不要…` / `要记住…` / `三条原则…` / 编号或项目符号列表 / `每当…就要…` / `只有…才能…` / `凡是…都…` / 作者在多处重复的同一条断言。

**产出格式**
```yaml
- id: p01
  title: Stop Doing List
  type: principle
  source_id: src-a
  source_chapter: 第 2 部分 · 投资篇
  source_quote: |
    "不做什么比做什么更重要。我们的 stop doing list 比 to do list 长得多。"
  summary: |
    主动列出"绝对不做"的清单，比列"要做"的清单更能防止重大错误。
    适用于投资、战略、职业选择等"错一次就伤筋动骨"的场景。
  tags: [principle, decision, negative-checklist]
```

**常见错误**
1. **把描述当原则** —— "作者告诉我们投资要谨慎"不是原则；"绝不投资你看不懂的生意"才是。
2. **把一整章当一条** —— 原则必须原子化，一章可能含 3–5 条独立原则。
3. **和 framework 混淆** —— framework 是"**怎么想**"，principle 是"**做不做**"。一个给推理方式，一个给 yes/no。

**上下文策略**：**全量扫描**。原则散落全文，且需判断"是否反复出现"。

## 3. case-extractor — 作者亲自使用的实例

**为什么单独抽**：案例本身不独立成卡，但它是阶 3 **V1 验证的关键证据**，也是阶 4 **A1 段的素材来源**。没有案例池，后面两步都会卡住。

**职责范围**：作者**亲自**经历/操作的决策与事件；作者转述但用来阐释某个方法论的他人案例。**每个案例必须绑定到一个方法论主题**，否则没有价值。

**不属于你**：纯背景叙事（没有方法论绑定）、虚构寓言（除非作者直接拿它说明方法）、作者的观点/原则/框架本身。

**识别信号**：具体年份 + 第一人称叙述 / "有一次…" / "某某公司的案例…" / "比如…" / 过去时叙述 + 伴随评论反思。

**产出格式**
```yaml
- id: c01
  title: 收购 See's Candy
  type: case
  source_id: src-a
  source_chapter: 第 5 讲
  source_quote: |
    "我们以 2500 万美元收购了 See's Candy…这是我们第一次为品牌溢价付费。"
  summary: |
    收购时放弃了格雷厄姆式的"便宜货"标准，转而为"有定价权的生意"付出溢价。
    这笔投资后来成为他们转向"优质企业 + 合理价格"策略的转折点。
  bound_to:                    # ★ 必须绑定到至少一个方法论主题
    - "能力圈 + 定价权"
  outcome: |
    该公司后续 30 年产生的现金流远超初始投资。
  tags: [case, investment, turning-point]
```

**自检**：每条都有 `bound_to`；有原文引用；`outcome` 尽量填。数量上传记/访谈类可能几十上百条，方法论书 10–30 条，都不应少于 5 条（否则阶 4 的 A1 段会空）。

**上下文策略**：案例是局部命中型，可用检索式定位后取邻接块防断章取义。

## 4. counter-example-extractor — 失败模式 / 反例 / 陷阱

**为什么单独抽**：反例是阶 4 **B（Boundary）段的核心素材**。没有反例，能力卡就没有边界，会在不该用的时候被调用，反而帮倒忙。**这是最能区分"蒸馏"和"书摘"的一类内容。**

**职责范围**
- 作者明确警告的失败模式
- 作者批评的错误做法
- 作者承认自己犯过的错
- 作者描述的反面典型
- 认知偏误 / 心理陷阱

**不属于你**：一般性的道德批评（没有可学习的机制）、作者情绪化的吐槽（没有论证）。

**识别信号**：`最大的错误是…` / `千万不要…` / `很多人以为…` / `失败的原因是…` / `陷阱在于…` / `我当年…`（+悔意）/ `人们往往…`（+负面）。

**产出格式**
```yaml
- id: ce01
  title: 过度自信偏误
  type: counter-example
  source_id: src-a
  source_chapter: 误判心理学 · 第 12 条
  source_quote: |
    "大多数人都认为自己比平均水平更聪明、更公正、更有能力。"
  failure_mode: |
    在自己不懂的领域自认为懂，做出超出能力圈的决策。
  mechanism: |
    人脑默认把"熟悉"等同于"理解"，把"喜欢"等同于"正确"。
    缺乏外部校正时，过度自信会随成功次数累积而强化。
  warning_signs:
    - 决策时感到"这很简单"
    - 没有 plan B
    - 不愿意向人请教
  bound_to:                    # 这个反例会限制哪些正面能力的适用范围
    - "能力圈判断"
  tags: [counter-example, cognitive-bias, overconfidence]
```

**自检**：每条都有 `failure_mode` **和** `mechanism`（不能只说"这是错的"）；`warning_signs` 尽量填（让 B 段有可识别的信号）；`bound_to` 说明它限制哪些正面能力。

**上下文策略**：局部命中型（有明确警告性措辞），可检索式定位。

## 5. glossary-extractor — 关键概念词典

**为什么要单独抽**：作者**用某个词的方式**往往和字典不一样。不统一术语，后面的卡会把作者特定用法的词当成日常义来用，完全失真。

**职责范围**：挑出满足**任一**条件的词 ——
1. 作者反复使用（全文 ≥3 次）
2. 作者明确定义过（"所谓 X，是指…"）
3. 看起来像常用词但作者用法与常识不同
4. 是核心论点的组成词

**产出格式**
```yaml
- id: g01
  term: 能力圈
  type: term
  source_id: src-a
  source_chapter: 第 2 讲
  author_definition: |
    "你真正能做出准确判断的知识边界。不是你知道什么，而是你知道'你知道什么'和'你不知道什么'的边界。"
  key_distinction: |          # ★ 最有价值的字段
    ≠ "熟悉的领域" —— 熟悉不代表能做判断
    ≠ "专业领域" —— 博士学位也可能在能力圈外
    = 能持续做出比市场更准判断的范围（需经实战验证）
  aliases: []                 # 多源项目必填：其他来源里对同一概念的不同叫法
  why_it_matters: |
    该词在所有决策类卡中都会出现。若沿用字典义，卡会建议用户"评估是否熟悉该领域"，这是错的。
  tags: [term, core-concept]
```

**多源项目额外要求**：`aliases` 字段必填。同一概念在不同来源里可能叫法完全不同（例如"复利"与"长期主义"、"责任/产权/杠杆"与"可扩展的资产"），必须在此对齐，否则阶 5 的术语表无法统一。

**数量预期**：每份材料 5–20 条核心术语。多于 30 条说明把一般词汇也收进来了。

**上下文策略**：局部命中型，可用词频预筛 + 检索式。

---

## 覆盖率硬门（所有 extractor 共用）

- 全量扫描是基线。改用检索式的 extractor，**最终通过验证的候选相对基线漏检数必须为 0**。
- 做不到就把该 extractor 退回全量扫描，Token 收益从别处找。
- 每次改动检索策略都要重跑一轮覆盖率对比，并把结果记进 `STATE.md`。
- **覆盖率优先于 Token 节省。** 对"是否已覆盖全部相关内容"没有把握时，宁可多查几轮。
