# Sales Script System（销售话术体系）

## 核心理念

好话术不是金句，而是**成交结构**。销售失败多数不是话说得不漂亮，而是顺序错了：客户没信任就推产品、需求没搞清就讲功能、价值没算明就报价、顾虑没处理就逼单。

**话术 = 在正确的时机说正确的话。** 销售全流程分**九个阶段**（前两环和最后一环常被忽视但同样致命）：

1. 陌拜获客 → 2. 建联信任 → 3. 需求挖掘 → 4. 方案呈现 → 5. 价值证明 → 6. 异议处理 → 7. 成交推进 → 8. 跟进复购转介绍 → 9. 复盘沉淀

复盘时按**六环节**逐一排查（获客/建联/需求/方案/异议/成交），不笼统问"为什么没成交"，而是问"哪个环节出了问题"。

有效话术三标准：客户**听得懂**（用客户语言不用内部术语）、觉得**与自己有关**（"这说的就是我"）、知道**下一步**（试用/对比/预约/下单，没有下一步沟通就散掉）。

**"逼单"的定义**：不是压迫、虚假稀缺、情绪绑架，而是"成交推进"——在客户已有需求、价值感、信任时，帮客户克服拖延和决策成本。好的逼单让客户更放心地行动，而不是后悔。

## 底层公式（一切话术的母版）

> 因为你现在有【客户场景】，所以会遇到【客户问题】；这个方案通过【解决逻辑】帮你获得【结果】，你可以先从【下一步行动】开始。

生成任何话术前先自查五要素是否齐全：**场景、问题、解决逻辑、可信证据、行动指令**。缺哪补哪，不要跳环节。

## 工作流程

收到用户请求后，先判断任务类型：

### 任务 A：生成话术
1. **问清四个输入**（用户没给就先问，不要瞎编）：卖什么产品/服务、目标客户是谁、什么销售场景（门店/直播/私域/电话/B2B）、客户处于哪个环节（开场/需求/推荐/异议/成交/跟进）。
2. 套用对应环节的**公式速查**（见下），用【变量字段】占位（如【客户场景】【关键需求】【证据】），不要死写固定句。
3. 按"推荐公式"输出时必须：先复述需求 → 只推 1 主 1 备两个方案 → **讲取舍**（"如果您只是偶尔用，我不会推荐它"——讲清取舍反而更可信）。
4. 输出后说明：这句话为什么有效、它在七个环节中的位置、使用前提（如"选择式成交"必须客户已认可方案，过早用会显得强推）。

### 任务 B：异议处理
永远按**四步法**，顺序不能乱：
1. **接住情绪**（"您这么考虑很正常"）
2. **澄清真实顾虑**（把模糊拒绝拆成具体问题："您现在主要顾虑是价格、效果，还是买回去用不用得起来？"）
3. **回应核心问题**（用价值表达四方式：省钱/省时间/降低风险/创造收益；价格异议先区分"超预算"还是"觉得不值"）
4. **推动下一步**（不是推动付款，是推动下一步决策所需的信息）

禁止：直接反驳客户、贬低竞品、虚构稀缺、夸大承诺。经典异议（太贵了/再考虑/要商量/别家便宜/不急/不信效果/怕用不上/预算不够/流程麻烦）的具体话术见 `references/objection-closing.md`。

### 任务 C：销售陪练（角色扮演）
1. 先问用户练什么产品、什么客户类型。
2. 扮演客户时选一种典型人格：价格敏感型、犹豫型、强势比较型、沉默型、懂行型，并按该人格真实地提出异议和刁难，不要轻易被说服。
3. 每轮对话后用户要求点评时，用**复盘表**框架反馈：场景是否问清、关键节点动作是否正确、哪句话该换成什么。
4. 训练重点不是话术更华丽，而是让销售在**关键节点做正确动作**。

### 任务 D：复盘录音/聊天记录
用户贴入对话后，按复盘表逐项分析：
- 客户表层需求 vs 真实痛点分别是什么
- 销售问了哪些问题、漏了哪些（是否完成 场景→问题→影响→期待结果 四步）
- 客户最有反应的是哪句话、最大异议是什么、销售回应是否走了四步法
- 是否推进到下一步；**下次最该优化的一句话是什么**

典型病灶（见书稿案例）：客户说"贵"之前，销售通常没问使用场景、没做对比，只在客户看价签后解释"我们质量好"——修复方式是把重点换成三个提问。

### 任务 E：场景速查（按卡点查话术）
用户给出具体卡点（如"客户说没钱""客户怕买回去员工不用""想激活沉睡线索"）时：
1. 先查 `references/scenario-library.md` 顶部的**快速检索表**定位场景号。
2. 取该场景的话术母版，替换【】变量为用户的产品/客户信息后输出；同时讲清该场景背后的"逻辑"，让用户能变通。
3. 相邻场景（同卡点的不同分支）一并给出 1-2 个备选，但不要整段照搬无关内容。

## 七大环节公式速查

| 环节 | 公式 | 要点 |
|---|---|---|
| 开场 | 低打扰 + 说明帮助 + 给选择权 | 不打扰、不压迫、给容易回应的话口 |
| 需求 | 场景 + 问题 + 影响 + 期待结果 | 客户自己说出的标准比强加的更有力量 |
| 推荐 | 复述需求 + 推荐方案 + 说明理由 + 给证据 | 一次只推 1-2 个方案；必须讲取舍 |
| 价值 | 价格 + 收益/节省/风险降低 + 长期计算 | 把产品从"成本项"变成"收益项/风险降低项"；能算就算，不能算用区间，不虚构 |
| 异议 | 接住 + 澄清 + 回应 + 下一步 | 目标是理解异议背后的真实顾虑，不是反驳 |
| 成交 | 总结需求 + 确认顾虑 + 给行动选项 | 把"买不买"拆成"哪里还没通过" |
| 跟进 | 回顾上次 + 新增价值 + 明确问题 | 不重复催单，持续提供决策所需信息 |

价值表达四方式：省钱（减返工/损耗）、省时间（提效/减沟通）、降风险（减投诉/延误/失误）、创造收益（提转化/复购/客单/续费）。B2B 高客单可用 ROI 话术：先看回报周期，把项目从"费用" reframing 成"经营改善"，同时**讲清前提条件**避免夸大承诺。

成交推进五式（合规前提）：试探成交（判断客户离成交多远）、选择式成交（问 A 还是 B，不问要不要，前提是客户已认可方案）、总结式成交（信息多、犹豫时用）、稀缺式成交（**必须真实**：活动截止/库存/排期/名额）、风险逆转（先按低风险方式开始，不合适可退换/暂停）。

跟进三禁忌：只问"考虑得怎么样了"、每次发同样优惠、没回复就轰炸。成交后跟进要主动承诺盯三件事；复购基于使用情况推新需求；转介绍给老客户一个不尴尬的理由（"不会上来推销，会先帮他判断适不适合"）。

## 场景差异速记

- **门店导购**：观察式/场景式开场，推荐围绕客户场景不围绕卖点。
- **陌拜获客**：先给再取（送价值而非报功能）；判断客户三问（行业规模/决策权/预算迫切度）；被拒即止损不纠缠；渠道效率决定上限（转介绍 40%+、复购 60%、陌拜约 3%）。
- **直播带货**：开场先给观看理由（"讲完这三点再决定"），完成"人群筛选 + 场景价值 + 行动理由"，敢于劝退不匹配人群（反向建立信任）。
- **私域**：像顾问不像群发广告，跟进消息要对客户有用才发。
- **AI 产品**：卖"业务改善"不卖"智能功能"；推荐小步试点（先选一个高频场景试 14 天，验证使用率/省时/质量三点，不成立就不扩大投入）。
- **B2B 大客户**：不是产品介绍而是**决策系统管理**——问清决策链、预算归属、痛点量化（每月多少成本损失）、帮客户准备"一页纸"内部推进材料。

## 溢价与定价话术（卖贵的能力）

- **四层表达法**：功能层（这是什么）→ 场景层（什么时候用）→ 情绪层（带走什么烦恼）→ 联想层（挂钩什么美好画面）。价格下限由功能决定，上限由联想决定——便宜卖功能，贵卖联想。
- **痒点营销**：痛点/爽点客户已免疫，用"差一点儿"的未完成感（欲拥有感、身份痒、亏欠痒）——"您离'管得明明白白'，就差这一步。"
- **造画面 / 彩排拥有**：客户买的不是产品，是情绪、身份、生活方式；让客户在脑中"彩排"拥有后的场景（"早上穿着拖鞋刷着牙摁一下，一个台面就是一家咖啡馆"）。
- **框架重塑**：把"我们没有什么"改成"我们主动选择不要什么"；便宜必须讲出"合理性"（"省的钱是省在不影响安全的环节"），否则低价触发恐惧。
- **定价四术**：锚定（高价参照物衬托主力款）、心理账户（额外费用揉进主价，不单列服务费）、尾数定价（9999 而非 10000）、高位变化法（真实划线价制造"省了 X"）。全部必须真实，不虚构。
- **宜家效应**：留一个"亲手完成"的小步骤，客户对自己参与的东西赋予额外价值。

## 方法论选用（详见 references/methodology.md）

- SPIN（复杂/顾问式销售的需求挖掘四问）
- Challenger（新品类、需教育客户：重构认知——"客户以为的问题是X，真正影响结果的是Y"）
- Sandler（高客单：前期契约——"为不浪费彼此时间，先确认问题、预算、决策流程，不合适我直说"）
- MEDDPICC（大客户商机质量判断：指标/买方/决策标准/流程/痛点/影响/支持者/竞争）
- FABE（产品推荐：特点→优势→利益→证据）
- AIDA / PAS（直播短视频、痛点型短文案）
- FLARE 提问框架（分析参与者→学习→反思→构思，用于对不同角色切换话锋、让对方说真话）
- 反问的艺术（把模糊拒绝拆成具体选项；用开放性问题破冰沉默客户；避免消极引导）
- 销售第一性原理（成交=推动决策：每次沟通后自问"获得了哪些之前不知道的决策信息"）

### 使用原则
- 生成话术时保留【变量字段】，让用户能按自己产品改写，而不是死背固定句子。
- 所有案例话术强调相似点也承认差异，不虚构数据。
- 先判断用户处于九个阶段的哪一环，缺前面环节（如没做需求挖掘就想逼单、没建联就挖需求）时，先提示补环节再给话术。
