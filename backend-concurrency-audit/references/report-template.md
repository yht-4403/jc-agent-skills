# 输出报告模板

## 使用方式

当用户要求正式评估、审计报告、压测报告或上线建议时，使用本模板。不要机械填满所有字段；缺少数据时写“缺少证据”，并说明需要补充什么。

## 快速结论模板

```text
## 结论
当前项目在已有证据下，更接近【低并发/中等并发/中高并发】阶段。

能证明：
- ...

不能证明：
- ...

建议：
- 当前阶段优先做 ...
- 暂时不建议做 ...
```

## 中小团队简化建议模板

```text
## 可以先不做
- 生产大流量压测
- 影子表/影子库
- 服务网格灰度
- 分库分表
- 全量链路追踪

## 必须做
- health 检查
- 外部可用性监控
- 错误追踪
- 核心接口压测
- 核心业务链路压测
- 可回滚版本

## 可以交给平台
- Sealos：部署、多实例、资源限制、弹性伸缩、基础运行状态
- Sentry：错误和性能问题
- UptimeRobot/Better Stack：外部可用性和通知
- Grafana Cloud/云厂商：指标、日志、告警
```

## 表达边界

用这些句式避免过度承诺：

- “当前证据只能说明...，不能直接证明...”
- “该容量结论仅适用于本次环境、数据量和流量模型。”
- “更保守的安全容量应预留 20%-30% 余量。”
- “如果部署在 Sealos，弹性伸缩能缓解应用实例压力，但不能解决数据库慢查询、连接池打满、Redis 热 key 或第三方 API 限流。”
- “当前阶段不建议上完整微服务，优先把单体模块化、压测、监控和回滚做好。”
