# 并发能力判断标准

## 使用方式

当用户要求判断项目处于低并发、中等并发、中高并发、高并发，或要求资源配置和架构演进建议时，使用本参考。所有区间都是经验参考，不是硬性证明。

## 核心概念

QPS/RPS 表示每秒请求数。并发数表示同一时间正在处理的请求数量。两者近似关系：

```text
并发数 ≈ QPS × 平均响应时间
```

AI 对话、文件处理、SSE/WebSocket 这类长耗时场景，可能 QPS 不高但连接数很高。

判断性能时至少看：

- QPS/RPS
- 并发数
- p50/p95/p99/max
- 错误率和超时率
- 测试持续时间
- 样本量
- CPU、内存、JVM GC
- MySQL 慢 SQL、连接数、锁等待
- Redis 命中率、延迟、热 key、大 key
- MQ 堆积和消费失败
- 外部 API 失败率和超时

## 并发等级

### 低并发

经验范围：

- 并发请求数：1-20
- 全局 QPS：1-50
- 单表数据量：10 万以内
- 典型系统：后台管理、小型 CMS、个人项目、课程系统
- p95 目标：500ms 以内

重点：

- CRUD 正确
- 分页查询
- 参数校验
- 登录鉴权
- 基础索引
- 统一异常和日志

### 中等并发

经验范围：

- 并发请求数：20-100
- 全局 QPS：50-300
- 单表数据量：10 万到 500 万
- 典型系统：小型 SaaS、小型电商、企业内部系统、AI 工具站
- p95 目标：300-800ms

重点：

- 慢 SQL 和索引
- Redis 缓存和限流
- 数据库连接池
- 接口耗时统计
- 核心业务链路压测
- 基础监控告警
- 上线回滚方案

通过参考：

```text
50-100 并发
持续 10-30 分钟
核心接口 p95 < 500ms
错误率 < 0.1%
CPU、内存、MySQL、Redis 无明显异常
```

### 中高并发

经验范围：

- 并发请求数：100-500
- 全局 QPS：300-1000
- 单表数据量：500 万到 3000 万
- 典型系统：成熟 SaaS、内容平台、小型社区、AI 对话平台
- p95 目标：500ms-1s

重点：

- 缓存穿透、击穿、雪崩
- MQ 异步任务
- 限流、熔断、降级
- MySQL 主从和读写分离
- JVM 和线程池调优
- 链路追踪
- 监控告警和容量规划

通过参考：

```text
100-300 并发
持续 30-60 分钟
核心链路 p95 < 1s
错误率 < 0.5%
数据库无持续慢查询堆积
```

### 高并发

经验范围：

- 并发请求数：500-5000+
- 全局 QPS：1000-10000+
- 单表数据量：3000 万以上
- 典型系统：大型社区、电商活动、AI 平台、IM、内容推荐

重点：

- 多实例部署和负载均衡
- Redis Cluster
- MySQL 主从、分库分表
- MQ 集群
- 服务拆分和服务治理
- 容灾、降级、灰度、成本控制

## 资源配置参考

资源配置只能作为起步估算，不能直接等同容量承诺。

低并发：

- Spring Boot：2 核 4G
- MySQL：2 核 4G，可同机或托管
- Redis：1 核 1G，可选
- 部署：单机单体

中等并发：

- Spring Boot：2 个实例，每个 2 核 4G 或 4 核 8G
- MySQL：独立 4 核 8G 或 8 核 16G
- Redis：独立 2 核 4G
- HikariCP：通常 10-50 起步，按 MySQL 能力和接口耗时压测调整
- 部署：多实例应用 + 独立数据库

中高并发：

- Spring Boot：3-6 个实例，每个 4 核 8G 或 8 核 16G
- MySQL：主从，主库 8 核 16G 起
- Redis：4 核 8G 起，必要时主从/哨兵
- MQ：按异步任务量引入

## 架构演进

推荐路线：

```text
单体 Spring Boot
  -> 模块化单体
  -> 单体 + Redis
  -> 单体 + Worker + MQ
  -> 应用多实例 + 独立 MySQL
  -> MySQL 主从 + Redis 高可用
  -> 按压力拆服务
  -> 服务治理与平台化架构
```

不要过早拆服务。以下情况优先不拆：

- QPS < 300
- 团队 1-3 人
- 数据量 < 几百万
- 没有明显模块瓶颈
- 缺少监控
- 运维能力弱
- 业务边界不稳定

可以考虑拆服务的信号：

- 某模块压力明显高于其他模块
- 后台任务或 AI 调用拖垮在线接口
- 模块发布频率差异很大
- 数据边界清晰
- 团队协作和发布风险明显上升

## AI 对话系统特殊判断

普通接口看：

- QPS
- p95/p99
- 错误率
- 数据库和 Redis 压力

AI 生成接口看：

- 首 token 时间
- 完整生成时间
- 流式中断率
- SSE/WebSocket 长连接数
- 并发生成数
- 模型失败率
- 超时和取消处理
- token 统计准确性
- 额度扣减准确性
- 降级策略

大规模压测 AI 模型时，优先用 Mock 模型服务模拟首 token、流式速度、失败率和超时；上线前再用真实模型做小流量验证。
