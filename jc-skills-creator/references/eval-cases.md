# JC Skills Creator V1 初始 Eval 案例

用于创建器自身的触发、模式和渐进加载前向测试。测试时只把“用户表达”和必要原始材料交给独立 Agent，不要暴露预期结果。

## 目录

- 正向触发
- 负向触发
- 相邻混淆
- 渐进读取
- 端到端英雄案例
- 结果记录

## 端到端英雄案例

### H01：从成熟母文档创建

输入：

- 一份有方法论、案例和作者观点的母文档；
- 三条真实用户请求；
- 两条相邻任务；
- 明确要求创建但尚未指定单 Skill 或套件。

通过条件：

- 先判断 Skill 是否应存在；
- 区分稳定机制、假设、Gotchas 和语气；
- 给出正负触发语料；
- 设计最小上下文结构；
- 面向终端用户时设计首次价值说明，材料齐全后不等待确认；
- 不复制整篇母文档；
- 在写文件前建立 Eval。

### H02：审查长 Skill

输入：

- 一个 400 行以上、包含固定轮次、比例、公理和大量案例的 Skill；
- 没有真实失败记录。

通过条件：

- 区分静态风险和已验证问题；
- 引用具体原文；
- 不因长度本身判死刑；
- 给出最小修改方向；
- 不擅自改文件。

### H03：根据失败迭代

输入：

- 原始请求；
- 实际加载 Skills；
- 错误输出；
- 当前 Skill；
- 一个不能被破坏的相邻请求。

通过条件：

- 定位失败层级；
- 优先修改最靠近根因的位置；
- 增加对应 Eval；
- 检查相邻回归；
- 不用全面重写代替诊断。

### H04：从作者机器迁移到零配置用户

输入：

- 一个会调用外部 CLI、OAuth 和本机辅助 Skill 的产品 Skill；
- 一个包含 Evals、发布记录和运行时 Reference 的混合目录；
- 要求小白在新机器完成完整流程。

通过条件：

- 列出套件内部、外部工具和作者本机隐式依赖；
- 套件外的方法引用被内聚为最小规则或 Script；
- 外部工具具有检测、官方来源、安装同意、授权链接/二维码、状态验证和回退；
- 不承诺绕过用户授权，也不静默安装软件；
- Evals、基准和发布记录移到开发仓库，高价值 Gotcha 留在运行规则；
- 在没有第三方运行包的环境中执行确定性脚本回归。
