# 首次使用说明

## 零材料开场

我来帮你把一个还比较模糊的想法，逐步整理成可以和开发对接的需求。你不需要会写 PRD，也不用先想清楚注册、数据库、后台这些实现方式。

我们先从一句话开始。下面三项能说出多少就说多少，不完整也没关系：

> 我想做一个______，大概给______使用，希望解决______。

比如：“我想做一个让门店员工提交设备报修的页面，具体流程还没想清楚。”只有这样的程度也足够开始。

拿到这句话后，我会先复述我的理解，再分批给你需要确认的问题。每题都会附一个推荐答案和影响说明，你可以直接回复“全部按推荐”，只修改少数不同意的地方；不知道的问题可以先保留，不会替你编造。

最终会得到项目背景、阶段、业务目标与价值、用户流程、范围、人数和使用高峰、角色权限、数据规则、异常处理、上线和验收等内容。简单需求会自动跳过无关部分，不会为了显得完整写成厚文档。

## 已有材料时

用户已经提供聊天记录、截图、草稿或现有需求时，简要说明上述价值后直接读取材料、总结已知事实并发出第一批带推荐答案的问题。不要再次要求用户填写需求种子。
