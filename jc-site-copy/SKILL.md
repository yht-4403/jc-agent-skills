# JC Site Copy

先定页面任务，再写字。官网的任务是让未决定的人采取一个行动；产品界面的任务是让已决定的人完成一件事。两套嘴不能混用。

## 首次回复

当前对话第一次触发时，读取 [首次说明](onboarding/core-introduction.md)，按用户语言输出，然后立即工作。后续不重复。

材料已经够判断页面任务时，介绍后直接分类并写/改。只缺会改变场景的一项时，问那一项：页面类型、读者，或希望他做的一个动作。不要先要品牌故事、竞品全文或完整功能清单。

用户已给草稿、截图或现有文案时，把它当底稿，不重盘目标。

## 边界

做：

- 为指定页面写、改、审计中文文案；
- 把全站规则收成一页 `COPY.md`；
- 指出空转词、重复说明和场景用错。

不做：

- 小红书 / 短视频笔记 → 转对应内容 Skill；
- 邮件序列、弹窗、广告批量素材；
- 只改布局、色板、动效 → 转界面设计 Skill；
- 编造用户量、百分比、客户名、时限；
- 把竞品原句搬进用户产品。

项目里已有 `COPY.md`、`DESIGN.md` 或 `PRODUCT.md` 时先读，遵守已确认的术语和禁区。没有这些文件也能按本 Skill 的场景预算工作。

相邻分流：通用英文转化套路且用户明确只要营销页、不要产品界面规则时，可用 `copywriting`。本 Skill 在中文站点、产品界面、或用户要求少说话时优先。

## 工作流程

1. **定场景**  
   只标一个主场景。登录后的工具、对话台、列表、设置默认是产品界面，即使它长得像官网。读取 [场景预算](references/registers.md)。

2. **定预算**  
   按场景取字数和允许的句子类型。超预算的说明段先删，不先润色。

3. **写或改**  
   能换成对象、动作、时限、次数、完成态的，不要用评价词。读取 [空转词](references/lexicon.md)。同一轮只改文案，不顺手重做视觉。

4. **验收**  
   对产品界面做删字测试：去掉所有完整说明句后，主路径仍必须可完成。对官网检查：是否只推动一个行动、主按钮是否说出用户得到什么、有没有不可证伪的大词。

5. **交付**  
   只给当前页需要的产物，不附使用说明书。

## 稳定判断

- 删掉后用户仍能完成当前任务的句子，默认删。
- 方式副词和范畴动词（轻松、高效、赋能、重塑、无缝）不能代替可观察结果。
- 产品界面允许的字：对象名、动作、状态、数据、不可逆后果。欢迎语、功能卖点、节标题下的介绍段禁止。
- 空态、错误、不可逆确认可以写完整句；日常列表页不行。
- 官网英雄区可以有一句副标题；产品界面页副标题默认为 0。
- 定价页不再解释产品是什么，只帮人选档。
- 没有用户提供的数字或客户，就不要写社会证明，改用机制或可检查规则。

## 交付

按任务给一种主产物：

- **改写**：按区块给出可用正文；附「删了什么 / 为什么」不超过 8 条。
- **新写**：按区块给出正文；营销页的标题和主按钮可附 2 个备选，产品界面不备选。
- **审计**：只指出问题位置和场景是否用错，不擅自改成全稿，除非用户要求改。
- **规范**：读取 [COPY 骨架](assets/copy-md-template.md)，按项目填成一页 `COPY.md`；不把空模板当最终规范，不写成长篇品牌手册。

每份产物开头用一行标明场景。不要输出内部文件名、路由名或本 Skill 的方法论清单。

## 核心 Gotchas

- 不要把「标题 + 副标题 + 功能介绍 + 欢迎语」套进登录后页面。
- 不要先把句子写完整再考虑删；先删到能用，必要时再补一个可检查的词。
- 不要为了友好而加说明。结构或默认值能让人懂，就不要加字。
- 不要把「了解更多」「立即开启」「开启新体验」当主按钮。
- 不要把竞品演示对话或 slogan 改写后当成用户产品文案。
- 不要在设置页、权限页、FAQ 里写愿景；这些位置学规则句，不学英雄区。

## 停止

页面任务会在「对话台 / 工具界面 / 转化首页 / ToB 方案 / 定价」之间切换，且用户没指定时，先确认场景再写。用户要的是视觉稿而不是字，停止写长文案并转交。
