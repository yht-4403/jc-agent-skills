# 前端文案优化

按页面任务改中文官网和产品界面上的字。官网可以说服人行动，登录后的工具界面只让人做事，不自我介绍。

普通写法容易把落地页结构整页套进产品：标题、副标题、功能说明、欢迎语。看起来完整，用起来吵。这里先判断这个页面要完成哪一件事，再决定能写多少字、哪些词必须删。

适合：官网首页、功能介绍、定价、ToB 方案、AI 对话台、登录后的列表和设置、已有草稿要删水。不适合：小红书笔记、邮件序列、广告素材、只改视觉不改字。

---

你现在卡在哪一类，直接对号：

1. **产品界面字太多**  
   登录后的列表、设置、对话台在解释自己。处理：先删说明段，只留对象、动作、状态。

2. **要写官网首页或功能介绍**  
   还没决定怎么开口。处理：ToC 写“做什么 + 多快 + 立刻行动”；ToB 写组织结果、证明和试用，不写新范式。

3. **定价或套餐选档**  
   读者在选哪一档。处理：这档给谁、价格、可数的额度。不再介绍产品是什么。

4. **已有草稿，空、吵或不像人话**  
   处理：标出空转词和重复句，按同一页面任务改一版，并说明删了什么。

5. **要把全站文案规则写进项目**  
   处理：产出一页 `COPY.md`，给后续生成当门禁。

通常从当前这一页开始，不一次写全站。你已经有草稿或截图，就直接改；只有页面类型都不清楚时，才问一件事。

---

判断顺序是：页面要完成什么 → 字数预算 → 能删的先删 → 留下的句子必须可检查。验收用删字测试：去掉所有非对象、非动作、非状态、非数据的句子后，用户还能否完成这件事。

本轮你会拿到其中一样：改写稿、新页面文案、问题清单，或项目文案规范。数字和客户名只使用你提供的；没有证据就不编社会证明。

把页面类型、读者、希望他做的一个动作发过来。有草稿就直接贴。答不上来的词可以空着。
