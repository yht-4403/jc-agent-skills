# 状态、目录与命令契约

## 目录

- 项目文件
- 状态机
- 任务输入格式
- 命令
- 恢复规则

## 项目文件

初始化生成：

```text
<项目目录>/
├── 项目配置.json     # 目标、完成标准、重试和质量门
├── 任务.jsonl        # 唯一任务账本，一行一个任务
├── 状态.json         # 项目状态和当前任务
├── 事件.jsonl        # 追加式状态变化记录
├── 进度.md           # 由脚本生成的人类视图
├── 产物/             # 建议产物位置
├── 复核/             # 每次复核的结构化记录
└── 协议/             # 项目自己的领域协议
```

不得把项目输入、产物或用户数据写入 Skill 源目录。

## 状态机

```text
待处理 → 进行中 → 待复核 → 已完成
             ↑        │
             └ 待返工 ←

任一未完成状态 → 已阻塞
待处理/待返工 → 已跳过（必须说明理由）
```

项目状态：

```text
运行中 / 已暂停 / 已停止 / 已完成
```

`提交` 只进入 `待复核`。任务只有在 `复核 --结果 通过` 后计入完成。

## 任务输入格式

`导入任务` 接受 UTF-8 JSONL，每行至少包含 `标题`。推荐：

```json
{"任务编号":"role-001","标题":"生成用户运营岗位 Pack","说明":"按岗位研究协议完成草稿","验收标准":["来源可访问","事实与推断分开","包含面试评分规则"],"输入文件":["协议/岗位研究协议.md"],"期望产物":["产物/role-001/pack.md"]}
```

可省略 `任务编号`，脚本自动生成 `task-001`。不得在导入文件中自行指定运行状态、尝试次数或复核结果。

## 命令

脚本位置记为：

```bash
python3 <Skill目录>/scripts/project_loop.py --项目 <项目目录>
```

### 初始化

```bash
... 初始化 --目标 "..." --完成标准 "..." --最大尝试次数 3
```

重复使用 `--质量门 "名称:已完成任务数"`。未提供时默认 `首批样本:1`。

### 添加与导入任务

```bash
... 添加任务 --标题 "..." --说明 "..." \
  --验收标准 "..." --输入文件 <路径> --期望产物 <路径>

... 导入任务 --文件 <tasks.jsonl>
```

可重复传入 `--验收标准`、`--输入文件` 和 `--期望产物`。

### 检查、状态和下一步

```bash
... 检查
... 状态
... 下一步
```

所有命令输出 UTF-8 JSON。`下一步` 的 `动作` 是后续操作的唯一依据。

### 领取与提交

```bash
... 领取
... 提交 --任务编号 <编号> --产物 <路径> --说明 "..."
```

`--产物` 可重复，路径必须存在且位于项目目录内；相对路径按项目目录解析。

### 复核

```bash
... 复核 --任务编号 <编号> --结果 通过 \
  --复核者 "人工/新上下文标识" --意见 "验证依据"

... 复核 --任务编号 <编号> --结果 返工 \
  --复核者 "..." --意见 "必须修复的具体问题"
```

返工后优先于新任务重新领取。达到任务的最大尝试次数后进入 `已阻塞`。

### 质量门

```bash
... 确认质量门 --名称 "首批样本" --确认者 "JC" --意见 "..."
```

确认只允许 Loop 继续，不代表所有后续任务自动合格。

### 暂停、恢复和停止

```bash
... 暂停 --原因 "..."
... 恢复 --说明 "..."
... 停止 --原因 "..."
```

停止是终态控制动作，但不删除文件。需要重新启动已停止项目时，应先人工审查状态，再创建新项目或显式修改方案；V1 不提供静默反悔命令。

### 跳过、阻塞和解除阻塞

```bash
... 跳过 --任务编号 <编号> --原因 "..."
... 标记阻塞 --任务编号 <编号> --原因 "..."
... 解除阻塞 --任务编号 <编号> --原因 "..." --追加尝试次数 1
```

跳过只适用于确认不在范围、重复或有明确替代证据的任务。解除阻塞必须说明外部条件发生了什么变化。

### 重建进度

```bash
... 生成进度
```

该命令从配置、状态和任务账本重建 `进度.md`。不要反向解析 `进度.md` 更新任务状态。

## 恢复规则

1. 先运行 `检查`；失败时修复结构，不继续领取。
2. 再运行 `状态`；以返回的 `当前任务` 和统计为准。
3. 有 `进行中` 任务时继续该任务。
4. 有 `待复核` 任务时先复核。
5. 有未确认质量门时停在质量门。
6. 没有以上情况时再领取新任务。
7. 事件日志只用于审计，不作为当前状态的替代来源。
