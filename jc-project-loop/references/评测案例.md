## 无 Skill 基线

真实已知风险：

- Agent 在对话中口头列 Todo，但没有持久化任务账本；
- 完成少量样本后提前结束；
- 上下文压缩后忘记早期约束；
- `提交` 被误当作质量通过；
- 失败后反复重试，没有停止条件；
- 产物散落，无法回答完成率和下一步。

## 应触发

1. “把这 80 个岗位依次做成岗位 Pack，维护进度，中断后能继续。”
2. “创建一个 Goal，按批次持续跑到首批质量门，不要每个任务都问我。”
3. “继续上次那个批量研究项目，先看真实状态再领取下一项。”
4. “用 `$jc-project-loop` 初始化这个项目，最大重试两次。”
5. “这批内容需要 Todo、进度表、返工和人工验收。”

必须表现：

- 建立或读取项目账本；
- 明确完成标准；
- 一次只推进一个任务；
- 每次状态变化落盘；
- 到质量门、阻塞或完成才停止。

## 不应触发

1. “解释一下用户运营是什么。”
2. “帮我修改这一个 Markdown 文件的错别字。”
3. “给我列一个今天的私人 Todo，不需要执行。”
4. “帮我设计 Redis 任务队列。”
5. “每天九点提醒我喝水。”

这些请求分别属于普通问答、单次编辑、清单、后端架构或定时任务。

## 相邻混淆

- `jc-learning-map`：负责画领域地图，不负责长期任务状态。
- `domain-sprint`：负责一次性深度拆解，不负责批量循环。
- `domain-skill-factory`：负责从资料构建领域 Skill，不负责所有通用项目。
- `domain-skill-loop`：负责领域资料切块、抽取、复核和发布；已有对应工程时优先使用它。
- `jc-project-loop`：只在任务类型更通用，且需要本地账本与恢复时使用。
- `skill-creator`：负责创建 Skill；不因创建过程有多步就自动触发本 Skill。

## 端到端场景

### 场景一：正常完成和质量门

1. 初始化项目；
2. 添加两个任务；
3. 领取第一个；
4. 生成真实产物并提交；
5. 复核通过；
6. `下一步` 必须返回 `质量门`；
7. 未确认前不得领取第二个；
8. 确认后完成第二个；
9. `下一步` 返回 `完成`。

### 场景二：返工和阻塞

1. 最大尝试次数设置为 2；
2. 第一次提交后复核返工；
3. 再次领取时尝试次数为 2；
4. 第二次复核仍返工；
5. 任务进入 `已阻塞`；
6. 不得自动第三次领取。

### 场景三：上下文恢复

1. 领取任务后结束当前 Codex 上下文；
2. 新上下文运行 `检查`、`状态`、`下一步`；
3. 必须返回同一个 `进行中` 任务；
4. 不得重新创建或重复领取任务。

### 场景四：进度视图漂移

1. 删除或人为破坏 `进度.md`；
2. 运行 `生成进度`；
3. 必须从 JSON/JSONL 恢复正确视图；
4. 不得用旧进度反写任务状态。

## 验收 Rubric

- 结构：Skill 目录和 YAML 校验通过；
- 边界：未引入被禁止的基础设施；
- 状态：非法状态转换会失败；
- 恢复：已有 `进行中` 任务不会重复领取；
- 质量：提交不计入完成，复核通过才计入；
- 停止：质量门、暂停、停止和阻塞都能阻止新领取；
- 重试：达到上限后不会继续；
- 审计：关键状态变化写入 `事件.jsonl`；
- 可读：人类界面和说明以中文为主；
- 回归：不会抢占单次任务、领域地图和定时提醒请求。
