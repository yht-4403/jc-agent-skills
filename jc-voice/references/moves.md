# 思路库

思路是这篇内容要完成的动作，与嗓音无关：先选嗓音，再从这里挑零到几个思路自由组合。不强制使用任何思路，一个都不用也合法。本文所有锚点与示例同样受主文件 L1.5 反 AI 味约束。

## 开头一句定位

第一句说清这篇是什么、给谁看、看完能做什么。

锚点（主理人嗓）："下面这篇文档的目的是，希望各位能够给我补充到足够多的信息，方便我给各位进行高质量的修改。"

## 自问自答

替读者把疑问说出来，再直接回答。适合前言、服务说明。

锚点："为什么要补充这么详细的信息？不能你直接给我改好吗？当然可以……"

## 负面对照定位

先说清自己不是什么，再说是什么。对照对象必须真实存在且读者熟悉，不虚构稻草人。

锚点："这里并不是闲鱼淘宝上的，找几个大学生，只会给你改改格式，完全不改内容的简历修改服务。"

## 场景化失败

用具体失败画面代替抽象卖点。

锚点："避免因为 HR 不懂技术，没看到关键词，看不懂你这份简历到底适不适合他们岗位，导致简历被 pass 或错过。"

## 流程分步

用户视角的编号步骤，每步主语是用户动作或用户收益。顺序不能乱，编号小瑕疵对外发布前可最小清理。

锚点：voice-explain.md 附录 C 的流程说明。

## 信号 → 诊断 → 处方

先列观察到的信号，再给诊断，再给一句处方。诊断、复盘类内容的常用结构，可搭配 dbs-action skill 使用。

锚点：dbs-action 的诊断报告结构（你描述的问题 → 我看到的信号 → 诊断 → 一句话处方）。
