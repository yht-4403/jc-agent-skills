# jc-voice 第一批 Evals（开发侧记录）

## 无 Skill 基线（2026-10-12，同会话实测）

无 skill 状态下要求"精简一份工具的产品介绍"，连续两轮输出：箭头链流程（A → B → C）、三项排比加括号注释、标签加冒号（"事实边界：""开始："）、否定开场（"不用先答问卷"）、风格自描述（"三份都是口语化直述体：正常陈述事实"）。两轮人工去 AI 味仍未达标，最终由用户本人手写版本定稿。结论：无锚点时模型默认退回产品说明书腔，一句"写得口语点"不足以修正。

## 端到端 Rubric

1. 全程一种嗓音，无中途换嗓、无两嗓平均混合。
2. 删掉形容词后意思成立。
3. 无箭头链、无三项以上排比、无标签加冒号伪标题。
4. 主理人嗓：主语"你 / 我"，口语连接词保留，无"本文旨在"。
5. dbs 嗓：有明确判断或诊断，无鸡汤句和安慰词。
5a. 说明嗓：通篇无自述人称与主理人身份（不出现"我做过…""我看过…"），身份可信度靠第三方陈述。
5b. 说明嗓：第一句是判断而不是铺垫；抽象名词（方法论 / 全链路 / 实操细节 / 实战标准）最多保留一个。
5c. 说明嗓：读者处境写到具体（如"照着示例跑不通"），不写成抽象价值词（"解决文档困惑"）。
5d. 说明嗓：收尾落在能做的事，不出现安慰或祝福（"你不用自己摸黑试""希望能帮到你"）。
6. 思路未强制套用（允许零思路）。
7. 卖点落到具体场景。
8. 用户确认过的原文未被重写成整齐专业版。

## 说明嗓锚点回归（虚构示例，仅示范结构）

同一句首屏介绍迭代三版，前两版被否掉，第三版确认并作为说明嗓锚点：

| 版本 | 写法 | 用户评价 |
|---|---|---|
| 一版 | 五个抽象名词连用（清单、结构、字段说明、完整方法、实操细节） | 缺代入感 |
| 二版 | 改用第一人称自述（"我都看过""我在几家做过"）＋三个读者卡点 | 代入感对了，但"不要说我之类的" |
| 三版 | 身份改第三方陈述＋保留三个读者卡点 | 确认，就是这个 |

锚点原文与反例见 `references/voice-explain.md` 附录 A、B。结论：**产品介绍的可信度由来源、口径、读者处境承担，不由自述人称承担。**
