# JC Voice 写作嗓音系统

核心：**嗓音和思路解耦**。嗓音管句子听起来怎样，思路管这篇内容要完成什么动作。先选嗓音，再按需挑思路，不强制任何思路。

## 用与不用

用：对外说明与对用户直接说话的内容——产品与服务介绍、README、功能介绍、前言、流程说明、交付引导、催材料、服务说明、复盘、诊断、观点表达、自媒体草稿。

不用：简历正文、官网与落地页、规则文档、评审标准、代码注释。这些各有归属，不抢。

## L1 共用底座（任何嗓音不得违反）

- 一句一件事，先说事再补解释。
- 具体场景代替抽象卖点：不说"提升通过率"，说"HR 没看到关键词把简历 pass 了"。
- 主语用"你"或"各位"；写自己时按嗓音决定用"我"还是"我们"。禁说明书腔（"用户可以通过……"）。
- 敢下判断，说清能做什么、不做什么、做不到什么。
- 删光形容词后意思必须仍然成立。
- **不表演锋利**。翻转句（"不是不会，是没被追问过"）、夸张（"追问到你答不上来为止"）、三连排比、否定式机锋（"也不给……这种编不出来的数字"）——这四种是 AI 露馅最快的修辞，属于官网首屏，不属于 README 和功能说明。痛点的力量来自说得准，不来自扎得狠。
- 禁用：滥用双引号（概念词、整句、整段都框起来）、三项以上整齐排比、标签加冒号伪标题、"赋能 / 打造 / 全方位"。箭头链表达流程和顺序时可以用（"上传 → 诊断 → 导出"），不用来装概念。

## L1.5 三条硬底线（2026-10-24 减重）

写稿时只守这三条。规则多了会挤掉语感，句子会变紧——这正是 10-21 版加到十条之后的后果。

- 不自造工程名词：说"进度检查点"不说"月度闸门"，说"清旧数据"不说"拆雷"，说"路径/步骤"不说"链路"。
- 段末不要句句抬金句。落在事实、数字或动作上，一段里只有一句可以"响"。
- 不补原文没有的内容：不添理由、不加案例、不编数据。

改稿的其余检查项（动词及物、比喻超量、格言句、中英混排、锁定文本等）在 [references/edit-checklist.md](references/edit-checklist.md)。**只在改稿时读，写稿时不要读**。

## L2 嗓音二选一

一篇内容只用一种嗓音，不中途换嗓，不平均混合。拿不准时先看读者是谁：**一群陌生人在评估一件东西 → 说明嗓；具体一个人在跟你打交道 → 主理人嗓。**

- **说明嗓（默认）**：产品与服务介绍、README、功能介绍、方法说明。不自述个人身份与资历（"我做过猎头"），可以用"我们"指代产品与团队。动笔前读 [references/anchors-chengzicv-web.md](references/anchors-chengzicv-web.md)，**只借第一层的结构，第三层的修辞是官网专用，不要搬**；再看 [references/voice-explain.md](references/voice-explain.md) 里的 README 短锚点与两版被否掉的反例。
- **主理人嗓**：对具体的人说话——前言、流程说明、交付引导、催材料、服务说明。允许"我"，靠关系建立信任。动笔前读 [references/voice-chengzi.md](references/voice-chengzi.md)，里面有用户确认的手写原文，先找语感。

原文锚点是嗓音的最高权威：规则与锚点冲突时，以锚点的语感为准。用户逐句确认过的文案是权威底稿，只做事实错误、不可验证承诺、平台硬限制的最小修正，不重写成"整齐专业版"。

## L3 思路库（可选）

思路与嗓音正交，自由组合，也可以一个都不用。见 [references/moves.md](references/moves.md)，现有：开头一句定位、自问自答、负面对照定位、场景化失败、流程分步、信号→诊断→处方。

## 交付前检查

- 删掉形容词后意思还成立吗？
- 卖点是否都落到具体场景，没有抽象价值词？
- 全程一种嗓音，没有中途换嗓？
- 有没有冒出说明书腔、箭头链、排比包装、鸡汤句？
- 说明嗓：没有个人身份与资历自述吗？第一句是判断而不是铺垫吗？抽象名词是否只剩一个？收尾落在能做的事、而不是安慰或祝福吗？
- 改稿任务：动过的地方对照 [references/edit-checklist.md](references/edit-checklist.md) 过一遍。
- 朗读一遍，拗口吗？
