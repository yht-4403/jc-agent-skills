# jc-company-research：公司调研倒推法

## Overview

调研范围不由"能查到什么"决定，由"接下来要说什么"决定。

多数人做公司调研的顺序是：先收集资料 → 再想怎么用 → 最后硬挤出结论。结果是一份看起来很全、但落到具体场合只会念百科的资料堆。本 Skill 把顺序倒过来：

```
先定输出（要说什么 / 要做什么决定）
  → 再定场景阶段（这家公司现在处在什么阶段、最缺什么）
  → 再定维度（六维里哪几维真正影响这次判断）
  → 再定深度（这一维查到什么程度算够）
  → 才是执行调研
```

倒推的价值在于少做无用功，以及**每一节调研都能落到一句能说出口的话或一个能执行的动作**。查完用不上的内容，不查。

## 触发信号

- 用户给出一个公司名，说"帮我调研一下"，但没说这次要用来干什么
- 面试前要了解目标公司、准备回答"你了解过我们吗"
- 见客户、写提案、做渠道谈判前要摸清对方状况
- 要判断一个生意机会、一家公司值不值得合作或加入
- 入职前或入职后要重新校准对这家公司的理解
- 做竞品分析、行业观察、日常商业调研

**不触发**：只问一个具体事实（"某公司去年营收多少"）；改简历、写面试台词、模拟面试（走 chengzicv 系列）；纯市场规模测算或财务建模。

## 核心设计决策

1. **倒推优先于收集**：没定输出之前不开始查资料。用户只说公司名时，先问这一句"这次调研要支撑什么"，再动手。
2. **六维有主次**：六个维度覆盖公司全貌，但一次调研通常只需要深挖两三维。全部深挖是浪费，也会冲淡重点。
3. **深度分级可验收**：每一维给出 L0—L4 的深度标尺，避免"查了很多但不敢下判断"和"只看了官网就下判断"两种极端。
4. **阶段推演是定位工具**：把公司放到发展阶段上，才能解释"它为什么现在要这个岗位 / 要这个合作 / 要这个东西"。
5. **证据必须分层**：已核实事实、推断、待确认三档分开写。混淆这三档是调研稿最大的可信度杀手。
6. **交付以口播为主体**：主产物是一段能直接开口讲的话，不是一份汇报文档。底稿是给自己被追问时翻的。
7. **不绑定求职**：同一套骨架服务面试、见客户、提案、生意判断、入职校准和日常调研，切换场景只换侧重和输出形态。

## 工作流程

### Step 0：先定输出（不可跳过）

在查任何资料前，确认两件事。用户已经说清就跳过，没说清就只问这两句：

1. **这次调研要支撑什么场合？**（面试 / 见客户 / 内部提案 / 生意判断 / 入职校准 / 竞品分析 / 纯了解）
2. **你要对谁说什么、或者要做什么决定？**

用户只给公司名时，不要自己假设场景，也不要先查资料再补问题。一次问清即可，不要反复追问。

### Step 1：把输出翻译成调研问题

按场合倒推。每行给出"要说的那句话"和"必须查清的维度"：

| 场合 | 要产出的那句话（本质） | 优先深挖的维度 |
|---|---|---|
| 求职面试 | "我理解你们现在要解决的是 X，我在这块有 Y" | 现状、缺点与问题、市场机会 |
| 见客户 / 销售 | "你们的生意卡在 X，我的方案对应的是 X" | 核心业务、缺点与问题、补救方向 |
| 内部提案 | "这个方向的判断依据是 X，风险在 Y" | 市场机会、竞争位置、补救方向 |
| 生意判断（投/做/合作） | "这笔生意成立的条件是 X，不成立的风险是 Y" | 核心业务、现状、市场机会、缺点 |
| 入职校准 | "我原来的理解是 X，来了之后发现实际是 Y" | 全部六维，重做一遍 |
| 竞品分析 | "它和我们差在 X，它的软肋是 Y" | 核心业务、市场机会、缺点 |
| 日常调研 | "这家公司大致是这么个状况" | 核心业务、现状 |

详细版和每种场合的追问清单见 [references/scenario-reverse-lookup.md](references/scenario-reverse-lookup.md)。

### Step 2：给公司定阶段

阶段决定需求，需求决定考核和动作。这一步做不出来，后面的维度选择会失焦。

```
公司发展阶段（起盘 / 抢占 / 经营 / 转型 / 守成）
  → 这个阶段最缺什么
  → 所以它现在要什么（岗位要求 / 合作条件 / 产品方向）
  → 所以这次调研要重点证明或验证什么
```

四个常见阶段的特征和对应关注点：

| 阶段 | 典型信号 | 最缺什么 | 调研重点 |
|---|---|---|---|
| 起盘 | 刚成立或刚立项、融资早期、团队小 | 把概念变成能交付的东西 | 团队背景、产品可行性、钱够烧多久 |
| 抢占 | 有产品在跑、增长快、招人猛 | 跑赢对手、占住位置 | 竞争格局、增长质量、组织能力 |
| 经营 | 增长放缓、开始抓利润和效率 | 投入产出比 | 成本结构、品类或产品线健康度、渠道效率 |
| 转型 / 守成 | 主业见顶、换方向或收缩 | 找到第二曲线或保住基本盘 | 主业真实状况、新方向投入、组织调整 |

阶段判断要有依据。说不清阶段的公司，用 [references/stage-inference.md](references/stage-inference.md) 里的信号清单去凑证据，不要凭感觉贴标签。

### Step 3：按六维定深度

六个维度：

| # | 维度 | 要回答的问题 |
|---|---|---|
| 1 | 核心业务与产品 | 靠什么赚钱，货盘或产品线长什么样 |
| 2 | 当前现状 | 最近一年的经营状况、渠道结构、组织变化 |
| 3 | 市场机会 | 赛道往哪走，增量在哪 |
| 4 | 缺点与现有问题 | 外部能看到哪些短板 |
| 5 | 补救方向 | 公司可能怎么解，同行怎么解的 |
| 6 | 我的切入点 | 如果是我做，从哪进 |

每一维按 L0—L4 定深度。**只把这次场合真正用得上的维度做到 L3 以上，其余停在 L1。**

| 级别 | 定义 | 够用来干什么 |
|---|---|---|
| L0 | 知道它做什么 | 打招呼 |
| L1 | 知道大致模型和位置 | 泛泛而谈 |
| L2 | 查到公开数据、产品线、近期动作 | 一般交流 |
| L3 | 能自己推出一个判断，并说清依据 | 面试、见客户、提案 |
| L4 | 有内部或一手的验证 | 做决定 |

绝大多数场合做到 L3 就够。**L4 不要靠猜，拿不到就标成待确认。**

### Step 4：执行调研

按 [references/research-protocol.md](references/research-protocol.md) 的来源优先级取证。三条硬要求：

1. 时效性信息必须联网核验，不靠记忆里的印象。
2. 每条结论标来源和日期。同一说法被多处转载不算多源验证，要追到原始出处。
3. 证据分三档写：**已核实事实 / 我的推断 / 待内部确认**。写法见 [references/evidence-layers.md](references/evidence-layers.md)。

### Step 5：写口播稿

主产物是一段能直接开口讲的话。风格、结构、长度按 [references/spoken-script.md](references/spoken-script.md)。

核心纪律：跟着 `jc-voice` 的 L1 底座走——一句一件事、具体场景代替抽象卖点、主语用"你/我"、敢下判断、删光形容词后意思仍成立；不用箭头链、整齐排比、伪标题和"赋能/打造/全方位"。

### Step 6：出底稿

底稿是给自己被追问时翻的，不是拿给别人看的。包含来源、日期、三档证据、还没查清的问题。见 [references/delivery-contract.md](references/delivery-contract.md)。

## 交付形态

默认交付两份：

```text
口播稿  —— 一段能直接讲的话，按场合控制长度
调研底稿 —— 来源、日期、三档证据、待确认清单
```

用户可以只要其中一份。只要底稿时不做口播；只要口播时，底稿里的三档证据仍然要在口播稿里用自然语言保持诚实（"我看到的公开信息是……这部分我不确定"）。

**半成品请求要接住**：用户说"我只想知道这家公司靠不靠谱""只帮我看看竞品"时，只做对应的维度和输出，不强行走完整流程。

## 边界

- 不编造数据、内部信息、HC、预算、组织秘密。
- 不输出录用概率、投资回报预测或"一定会成功"的判断。
- 拿不到的信息进入待确认清单，并在口播稿里如实说明——这是加分项，不是短板。
- 公开信息缺口本身可以成为谈资：说清外部能看到什么、看不到什么、你打算怎么补。
- 个人经历和数字只能来自用户提供的材料，不能替用户补写。

## 验收用例

### 用例 1：完整面试调研

用户说"帮我调研一下某公司，下周要面试产品岗"。

必须：

- 先确认面试轮次和岗位职责范围，再去查
- 给出阶段判断并说明依据
- 六维里至少现状、缺点问题、市场机会做到 L3
- 口播稿能支撑"你了解过我们吗"和"你对我们内部规划有什么想法"
- 底稿里三档证据分开，拿不到的数据进待确认

### 用例 2：用户只给公司名

用户说"帮我调研一下某公司"。

必须：

- 先问"这次调研要支撑什么场合、你要对谁说什么"
- 不先查资料再补问题
- 用户答完后按场合倒推，不默认按面试准备

### 用例 3：见客户前的调研

用户说"下周要见某公司谈合作"。

必须：

- 输出重心落在对方生意卡在哪、我的方案对应什么
- 查对方近期的渠道、产品、价格动作，而不是公司历史
- 口播稿是"见面时怎么开口讲对方"的版本，不是自我介绍

### 用例 4：只要一部分

用户说"我只想知道某公司靠不靠谱，要不要接这个 offer"。

必须：

- 不强行走六维全流程
- 聚焦核心业务、现状、缺点问题，给出带条件的判断
- 明确说清哪些是他自己需要去核实的

### 用例 5：信息很少的公司

用户给的公司几乎查不到公开信息。

必须：

- 如实说明外部信息缺口，不硬凑
- 把缺口转成确认清单和可问的问题
- 口播稿仍然可用：讲清能看到的、看不到的、以及你打算怎么补
