# 触发与边界评测用例

用途：验证这个 Skill 在该触发时触发、不该触发时不触发，以及核心纪律是否被执行。新增或修改内容后跑一遍。

## 应触发

| # | 用户输入 | 期望行为 |
|---|---|---|
| T1 | "帮我调研一下某某公司，下周面试产品岗" | 先确认轮次和岗位，再按面试场景倒推；给阶段判断；出口播稿 + 底稿 |
| T2 | "下周要见 A 公司谈合作，帮我摸下他们情况" | 重心落在对方生意卡在哪；口播稿是讲对方的版本 |
| T3 | "我想看看这个赛道还有没有机会" | 走市场机会 + 竞争位置；出提案型口播 |
| T4 | "这家公司靠不靠谱，要不要接这个 offer" | 只做核心业务/现状/缺点问题；给条件判断，不给绝对结论 |
| T5 | "帮我看看 B 公司和我们比差在哪" | 竞品分析模式；必须找出对方软肋，不做赞美稿 |
| T6 | "我刚入职，想重新捋一下这家公司" | 入职校准模式；调旧底稿逐条对照；允许六维全做 |

## 不应触发

| # | 用户输入 | 应走哪里 |
|---|---|---|
| N1 | "帮我查一下某公司去年的营收" | 直接查答，不启动整套流程 |
| N2 | "帮我改一下简历里的项目描述" | chengzicv-resume 系列 |
| N3 | "把这段自我介绍写成面试台词" | chengzicv-interview-script |
| N4 | "帮我模拟面试，问我五个问题" | chengzicv-interview-mock |
| N5 | "帮我做一份这个行业的市场规模测算模型" | 不做，说明边界（本 Skill 不做财务建模） |
| N6 | "复盘一下我昨天那场面试" | chengzicv-interview-review |

## 核心纪律断言

以下是最容易走偏的地方，跑用例时重点看：

| # | 断言 | 违反表现 |
|---|---|---|
| A1 | 用户只给公司名时，先问场合，不先查资料 | 直接开始输出公司概况 |
| A2 | 阶段判断带依据 | 只说"这家公司在快速扩张期"，说不出凭什么 |
| A3 | 只深挖用得上的维度 | 六维全部拉满，输出几万字 |
| A4 | 每条结论有来源和日期 | 出现无出处数字 |
| A5 | 三档证据分开 | 把推断写成事实 |
| A6 | 拿不到的信息明说 | 用模糊表述掩盖数据缺失 |
| A7 | 口播稿能顺读，无禁用词 | 出现箭头链、整齐排比、"赋能/打造/全方位" |
| A8 | 口播稿里三档证据都有自然语言表达 | 全是硬结论，或全是不确定 |
| A9 | 半成品请求不强行走全流程 | 用户只要"靠不靠谱"，输出完整六维报告 |
| A10 | 不做录用概率或投资回报预测 | 出现"大概率能拿到 offer" |

## 边界压力测试

| # | 场景 | 期望行为 |
|---|---|---|
| P1 | 公司几乎查不到公开信息 | 如实说明缺口；把缺口转成可问的问题；口播稿仍可用 |
| P2 | 用户坚持要一个结论 | 给条件判断（如果……那就……），不编数据 |
| P3 | 用户提供的公司名有歧义（同名公司） | 先澄清是哪一家，不猜 |
| P4 | 查到的信息互相矛盾 | 并列呈现两边来源，标成待确认，不自行选一个 |
| P5 | 面试在明天，时间不够查完六维 | 砍维度不砍诚实；明说哪些没查 |
| P6 | 用户想拿这份调研去公开传播 | 提示底稿含未核实推断，不宜直接外发 |
