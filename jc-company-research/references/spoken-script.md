# 口播稿写法

用途：把调研结果变成一段能直接开口讲的话。这是本 Skill 的主产物。

跟着 `jc-voice` 的 L1 底座走。若 `jc-voice` 可用，动笔前读它；不可用时本文件已内联必要规则，直接按本文写。

## 三条不可违反的纪律

### 1. 一句一件事

先说事，再补解释。不写长定语套长定语。

- ❌ "作为一个在消费品领域具备从品类规划到上市运营完整链路经验的候选人，我对贵司所处的个护赛道有以下几点观察"
- ✅ "我看了下你们的情况。三个点想跟你们确认。"

### 2. 具体代替抽象

不写"提升效率""优化结构"这类抽象价值词，写具体到了什么程度。

- ❌ "可以帮助提升品线经营效率"
- ✅ "把洗护线的毛利结构拆一遍，先找出哪几个 SKU 在拖后腿"

### 3. 敢下判断，也敢说不知道

- 有依据的判断直接说，不要用"可能""也许"层层包裹。
- 没有的信息直接说没有，并说清你打算怎么补。

- ❌ "这方面的数据可能还需要进一步了解才能做出判断"
- ✅ "这块我没有内部数据。要判断机会在哪，得先看销售现状、回购、连带销售和流失走向这几组数。这些进来才能看到。"

## 禁用清单

- 箭头链（A → B → C）
- 三项以上的整齐排比
- 标签加冒号的伪标题（"洞察：""破局：""核心逻辑："）
- "赋能 / 打造 / 全方位 / 闭环 / 抓手"
- 鸡汤句和总结句（"总而言之，只有真正理解用户才能赢得市场"）
- 说明书腔（"用户可以通过以下方式……"）

写字前自问：删光形容词之后，这段话的意思还成立吗？不成立就重写。

## 长度控制

按场合定，不要一份稿子到处用：

| 场合 | 口播稿长度 | 说明 |
|---|---|---|
| 面试（"你了解过我们吗"） | 60—90 秒，约 200—300 字 | 一口气讲完，中途要给对方插话的空 |
| 面试（"你对内部规划有什么想法"） | 30—45 秒，约 120—180 字 | 短，重点是数据缺口那张清单 |
| 见客户开场 | 45—60 秒 | 讲对方的生意，不讲自己 |
| 内部提案 | 90—120 秒 | 允许长一点，但要有明确结论在前 |
| 生意判断 | 60—90 秒 | 条件判断句式 |
| 日常调研 | 30 秒 | 三句话说完 |

宁可短。讲不完可以留到回答追问时用。

## 结构模板

### 常识型（面试通用、见客户）

```
第一句：我看了什么（一句话交代信息来源和边界）
第二句：我理解你们现在的情况是 ___（阶段判断）
第三句：所以最要紧的是 ___（对方的核心问题）
第四句：我在这块做过 ___（我的对应证据，一句就够）
第五句：进来/合作之后我会先从 ___ 入手（具体动作）
```

### 数据缺口型（被问内部规划）

```
第一句：我没有 ___ 的数据，所以现在判断不了机会在哪
第二句：要判断的话，得先看 ___、___、___ 这几组
第三句：这些拿到之后，我大概会从 ___ 开始看
```

三句都要有。只讲第一句是推卸，只讲第二句是卖弄，三句齐了才是专业。

### 条件判断型（生意判断）

```
第一句：这事成立的条件是 ___
第二句：目前公开能看到的是满足了 ___ 条，还差 ___
第三句：如果我判断错，最可能错在 ___
第四句：所以建议先验证 ___
```

## 开场句库

不要用"我做了很多调研""我对贵司进行了深入研究"开头。可选的开场：

- "我看了下你们公开的信息，理解大概是这样的——"
- "有三个点我比较关注，也想跟你们确认一下。"
- "先说我的理解，如果说错了你们纠正我。"
- "我看到的公开信息有限，所以说错的地方你们直接打断。"

最后一句特别好用：它把"调研不完整"提前变成诚实，而不是被对方发现。

## 收尾

不要总结。收在动作或问题上。

- ✅ "所以我想确认的是，你们现在最缺的是哪一块。"
- ✅ "这块的判断我得看到数据才能给，别的部分我可以先讲。"
- ❌ "综上所述，我相信我的经验能够很好地匹配贵司的需求。"

## 底稿三档在口播里的表达

见 `evidence-layers.md` 的对照表。要点：已核实的说"我看到的公开信息是"，推断的说"我的理解是，不一定准"，待确认的说"这块我没有数据"。

三种说法都要出现。全是硬结论像口嗨，全是不确定像没做功课。

## 交付前朗读检查

写完读一遍出声，检查：

- [ ] 有没有一句话长到需要换气两次
- [ ] 有没有出现禁用清单里的词
- [ ] 每句是不是都在说具体的事
- [ ] 有没有"我"和"你们"，还是通篇第三人称
- [ ] 删掉形容词后还成立吗
- [ ] 时长对不对
- [ ] 结尾是动作或问题，不是总结
