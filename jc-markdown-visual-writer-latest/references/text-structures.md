# 文本结构模板

当 Mermaid 没必要、渲染环境不稳定，或用户需要纯 Markdown 时，用这些结构。

## ASCII 树

适合把 `graph LR` 的逻辑变成纯文本兜底。

```text
点击运行
 └── 是否通过运行前校验?
      ├── [否] --> 错误处理
      │     ├── 空脚本: 按钮不可点
      │     ├── 只有开始: 播 audio...
      │     └── 缺开始: 播 P5-1-16...
      │
      └── [是] --> 按右侧视觉顺序执行
            ├── lemon: 显示柠檬动作
            ├── soda: 显示小苏打动作
            └── observe: 快照结算
                  ├── lemon+soda都有 --> 成功反馈 P5-1-9
                  ├── 缺 lemon+soda --> 提示 P5-1-14
                  ├── 缺 lemon --> 提示 P5-1-13
                  ├── 缺 soda --> 提示 P5-1-12
                  └── 后续还有动作 --> 疑问态...
            └── (整轮无 observe) --> 执行已有材料...
```

习惯：

- 结构清楚比完全对齐更重要。
- 分支名用 `[是]`、`[否]`、`(特殊情况)` 这类短标签。
- 很长的说明用 `...` 截断，细节放后面的列表或表格。

## 正常无序列表

适合知识沉淀、规则整理、普通回答。

```markdown
- 点击运行
  - 校验失败
    - 空脚本：按钮不可点
    - 只有开始：播放提示，不进入 running
    - 缺开始：播放 P5-1-16
  - 校验通过
    - 执行 lemon
    - 执行 soda
    - 执行 observe 并结算
```

## 序号列表

适合 SOP、执行步骤、排查过程。

```markdown
1. 点击运行后先做运行前校验。
2. 校验不通过时播放对应提示，并阻止进入 running。
3. 校验通过后，按右侧视觉顺序执行动作。
4. 执行到 observe 时，按当前快照结算反馈。
5. 整轮没有 observe 时，末尾提示缺 observe。
```

## 决策表

适合多条件对应多结果。

```markdown
| 场景 | 系统行为 | 反馈 |
| --- | --- | --- |
| 空脚本 | 按钮不可点 | 无 |
| 只有开始 | 不进入 running | 播 audio |
| 缺开始 | 不进入 running | 播 P5-1-16 |
| lemon+soda 都有 | 成功结算 | P5-1-9 |
| 缺 observe | 执行已有材料 | 末尾提示 P5-1-11 |
```

## 检查清单

适合验收、开发计划、复盘后行动。

```markdown
- [ ] 空脚本时按钮不可点
- [ ] 只有开始时不进入 running
- [ ] 缺开始时播放 P5-1-16
- [ ] observe 能按快照结算
- [ ] 整轮无 observe 时末尾提示缺 observe
```

## 组合建议

常用组合：

- 复杂业务逻辑：`graph LR` + ASCII 树。
- 正式流程：`flowchart TD` + 决策表。
- 模块交互：`sequenceDiagram` + 关键规则列表。
- 状态变化：`stateDiagram-v2` + 状态说明列表。
- 日常知识沉淀：无序列表 + 检查清单。
