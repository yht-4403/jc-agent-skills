# 历史失败与处方

收到修改意见、或交付前自检时读本文件。这些不是假想，是 2026-10-26 一次真实交付里发生过的，从九节 3000 字被改到六节 1400 字。

## 目录

- 症状速查
- 逐条复盘
- 失败的共性

## 症状速查

| 症状 | 病根 | 处方 |
|---|---|---|
| 文档很长，客户还是来问 | 写了"全面"，没写"下一步做什么" | 每节只留一个动作 |
| 客户照着找不到按钮 | 用了内部行话，没抄界面文字 | 截图上的字照抄，路径写成点击链 |
| 客户卡在第 2 步 | 让他做了一件此刻做不到的事 | 前置准备动作，或改成"先看位置" |
| 图注写错，路径跟着错 | 看图不细，凭印象命名 | 图注必须能在图上逐字找到 |
| 文档像宣传册 | 混进优势、对比、承诺 | 移出到提案或聊天 |
| 换个客户就不能用 | 混进真实账号、客户名 | 抽成一组虚构示例值 |
| 客户 20 分钟来催一次 | 没写我方动作和时限 | 加"我这边做什么"节 |
| 手机截图看不清 | 竖屏图按容器宽度缩放 | 显式限宽 430–460px |

## 逐条复盘

**1. 第一版写成服务协议（九节 3000 字）**

含：账号说明、低价号对比表、如实告知、交付清单、账号信息卡、使用说明、开通流程、费用发票、售后边界、确认回执。

病根：把"给采购和财务看的"和"给现在要登录的人看的"混在一份文档里。角色不同，关心的东西不同。

处方：操作指引只留客户此刻的动作。条款、价格、售后承诺移出，留在聊天或合同。判断法是问"客户现在会读这一段吗"，不会就删。

**2. 用了客户发来的 3 张截图**

客户截图里含他自己的账号、验证器搜索页、验证码页。

病根：只判断了"内容对不对"，没判断"来源合不合规"。

处方：图片只用服务方自己截的。客户截图有三个问题：带真实信息、换个客户不能复用、客户看到自己的截图会困惑。

**3. 把 ChatGPT 的设置页误标成谷歌账号页**

图里左侧菜单是「个人资料 / 账户安全与登录 / 已归档的聊天 / 语音 / 存储」，明显是 ChatGPT；但文件名被起成 `04-google-mfa`，图注也按谷歌写，导致正文路径"谷歌账号 → 安全 → 多因素身份验证"配了张 ChatGPT 的图。

病根：看图不细，凭文件名和印象推断，没有逐字读界面。

处方：图注里的词必须在截图上能逐字找到；文件名按内容起，不按猜想起；改完名字同步改引用。界面真实路径是「设置 → 账户安全与登录 → 多因素身份验证（MFA） → 身份验证器应用」。

**4. 手机截图在正文里被压到 330px**

竖屏截图按容器宽度缩放，界面文字看不清。

处方：竖屏图显式限宽 430–460px（md 用 `<img width="450">`，HTML 用 `figure.phone`）。

**5. 确认环节写成了"确认要开的是 Pro 档"**

还展开讲四档套餐、20x 额度。

病根：把"确认东西能用"写成了"确认产品规格"。客户此刻只需要知道账号是活的、能充值。

处方：确认环节只证明"可用"。规格、档位在聊天里谈。删掉之后还能少一张图。

**6. 正文写了真实账号（此处以 `@demouser101`、`demouser101@example.com` 示意）**

病根：当成一次性文档在写，没考虑复用和泄露。

处方：抽成一组虚构示例值，格式合法、一眼看出是假的、全文同一组，并注明"以实际发的为准"。

**7. 客户中午 12:41 来问"还没好吗"**

病根：文档里没有任何我方动作和时限，客户不知道要等多久。

处方：单独成节写"我这边做什么 + 时限 + 你此刻别做什么"。

**8. 差点让客户在没有 App 的情况下点"启用"**

多因素认证排在"装 App"之前，按知识点顺序排就必然如此。

病根：按知识结构排序，没按客户的手排序。

处方：这一步改成"不用点启用，手机上还没装 App，做不了，记住位置就行"，并在第四节给出回来路径（"回到第三节第 4 步那个页面"）。

## 失败的共性

八条里有六条不是"写得不好"，而是**视角错位**：

- 写给了错误的读者（采购而不是操作者）
- 排给了错误的主体（知识点而不是客户的手）
- 选了错误的素材（客户截图而不是自己的）
- 用了错误的参照（印象而不是屏幕上的字）

真正的文字功夫占比很小。改稿时优先检查视角，其次才是措辞。
