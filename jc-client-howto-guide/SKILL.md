# 客户操作指南文案

把服务方的操作知识，编译成客户照着能做完的图文指引。验收标准只有一条：**客户读完做完，不用来问第二遍。**

## 何时使用

- 交付实物、账号、软件后，需要一份"接下来怎么用"
- 客户在微信里反复问同样几个操作问题
- 流程有 3 步以上，且顺序错了会出事（先装软件才能绑、先确认才能付款）

**不适用，直接说明并停止**：

- 产品介绍、销售提案、报价 → 不是操作指引
- 纯文字润色 → 不接
- 内部 SOP、给同事的文档 → 直接写，不必走本流程
- 创建或审查 Skill → 转 `jc-skills-creator`

## 三条判断基准

### 1. 一份文档只回答一个问题

"拿到东西之后怎么办"。其他一律删除：公司介绍、优势对比、售后条款、发票流程、确认回执、FAQ 大全。

### 2. 三把删除尺

逐句过，任一命中就删：

| 尺子 | 判断 |
|---|---|
| 删了客户会不会做错？ | 不会 → 删 |
| 这句在证明"我们专业/靠谱"吗？ | 是 → 删（专业靠步骤精确度体现） |
| 这是承诺、价格、条款吗？ | 是 → 移出文档，留给聊天或合同 |

第三条最易忽略：教学文案里的承诺会被客户当依据。质保、期限写在聊天里，不写在指引里。

### 3. 按客户的手排序，不按知识结构

排序判据只有一个：**客户此刻手能不能动。**

做不了 → 前置一个准备动作，或降级成"先看位置，不操作"。

> 实例：ChatGPT 多因素认证排在"装验证器 App"之前，但写明"这一步不用点启用，手机上还没装 App，做不了，记住位置就行"。客户不会卡在第 4 步。

## 五步流程

1. **挖素材**：翻聊天记录、录屏、工单，列出客户问过的每个问题。问过就是真实痛点，没问过的基本是自嗨。
2. **排时间线**：按真实发生顺序写一行，标出谁在动（客户 / 我方）。
3. **砍**：用三把尺子逐句删，删到自己觉得"是不是太少了"——通常这个位置刚好。
4. **配图**：每个关键动作一张，检查来源与位置。
5. **三遍校对**：客户视角（哪步会卡住）→ 手机视角（每节能否一屏读完）→ 安全视角（有无真实账号、客户名、收款码、内部定价）。

## 硬约束

- **指令三段式**：做什么 + 在哪里（点击链）+ 做对了长什么样。判断标准必须是可观察现象（页面弹出来、出现某行字），不能是"成功""正常"。
- **界面用词照抄**：写客户屏幕上实际显示的字，不翻译成内部行话。术语首次出现给中文对照。
- **示例值一组贯穿**：格式必须合法（如 Base32 密钥 16 位），一眼看出是虚构，全文同一组，并注明"以实际发的为准"。格式不合法的示例会让客户填不进去，反而更慌。
- **图片只用服务方自己的截图**：客户发来的图含真实信息，且换个客户就不能复用。
- **图注写"要你看什么"**，不写"截图"。图里是未完成状态（开关是灰的、排队中）时，文字必须说明"图示为操作前状态"，否则客户以为坏了。
- **强度分级**：只有会导致封号、丢数据、损失钱的，才做独立警示块（放大加粗 + 写清后果）。全文都加粗等于没有重点。

## 资源导航

- 写文档结构、确定各节内容时读 `references/document-skeleton.md`——六节骨架、每节该写什么、强度分级、交付前自检清单。

## 交付契约

同时产出两份，不要只给一份：

- `.md` —— 源文件，便于导入腾讯文档 / 飞书 / Notion
- `.html` —— 可直接预览效果、发链接或打印。浅色底，正文 ≥15px，图片限宽

图片素材放同级 `assets/`，语义化命名（`01-login-ok.jpg`、`04-chatgpt-mfa.jpg`）。md 里用 `<img width>` 控制竖屏截图宽度，避免撑满整行。改文件名必须同步改引用，改完核对一遍引用与文件是否一一对应。

## 核心 Gotchas

- 不要把"看起来专业"当内容。对比表、质保条款、确认回执会挤掉客户真正要做的动作，第一版写九节 3000 字就是这么废掉的。
- 不要让客户做他此刻做不到的事。没装 App 就让他绑验证器，客户会卡在那里等你回答。
- 不要凭印象写界面路径。图注里的字必须能在截图上逐字找到，否则路径跟着错。
- 不要只做整段加粗。全文都重，等于没有重点。
- 不要用客户发来的截图。即便内容对，也不可复用、且带真实账号。

## 停止条件

- 拿不到真实操作路径或界面截图 → 不编造，向用户索取
- 素材含客户隐私且无法脱敏 → 先脱敏，否则不产出
- 需求实为产品介绍、报价或合同 → 说明不在本 Skill 范围，转给相应能力
