# 报价与压价应对

## I — 方法论骨架 (Interpretation)

报价不是一个数字，而是**一份关于"空间留在谁手里"的决策**。

作者 2025 年的立场很明确：**空间交给客户，不留在自己手上**。报两段，第一段就是低价，报的不能是虚高价、不能是空间太大的价；把"只能脱一次裤子的报价"直接拿出来，让客户自己去往上加。原因是环境变了——客户被友商和友商的友商教育透了，绝大多数找上门的都是**询价客**，价格是入围门槛而不是谈判起点；还玩"先聊价值再聊价格"很危险。

但在报价之前，有三道前置判断，缺一道都会报错价：

1. **客型分流**：这个客户是"纯询价客"（已多渠道比价、把价格当入围门槛），还是"需求待澄清客"（还不确定要不要买、需要你先帮他定义需求）？前者直接给真实低价；后者先做状态判断、先聊需求。
2. **有没有预算**：没有预算/消费能力不足的，**不是客户**——在第一圈就筛掉，不要用报价去"培养"他。
3. **这是不是结构性的价格劣势**：如果客户的核心诉求就是"便宜"，而你天生贵，技巧赢不了结构性劣势。此时要么改变参与方式（如低配版、分段交付），要么承认这一单不该抢，别把项目神化成商战故事。

被压价时的正确动作是**把价格换算成客户的损失与收益**（返工成本、停机损失、替代方案的隐性成本），而不是继续降价——降价只能打一次，算账可以一直用。

## A1 — 案例 (Past Application)

### 案例 1: 外企学员觉得"两倍定价必死"
- **问题**：一位外企产品的销售，产品价格是国产同类两倍，陷入自我怀疑，认为必死。
- **方法论的使用**：作者带他做客户侧的账——把客户的真实损失与收益算出来（而非比较单价）。
- **结论**：贵不贵要由客户的使用成本判断，不由单价判断。
- **结果**：价格劣势被翻译成了可讨论的 ROI 议题。（p84）

### 案例 2: 测量不准返工 600 件，一次损失约 50 万
- **问题**：客户觉得便宜的产品够用。
- **方法论的使用**：作者用客户侧的真实损失案例算账：返工 600 件直接损失 18 万，加上下游停线合计约 50 万/次。
- **结论**：把"差价"和"一次事故的代价"放在同一张纸上，价格比较就有了参照。
- **结果**：算账取代了降价。（p84）

### 案例 3: 客户说"你们产品偏贵"的两种接法
- **问题**：客户当面说"你们偏贵"。
- **方法论的使用**：错误接法是辩解"我们不算贵，属于中游"；正确接法是承认+反抛一个可继续的问题（"您对比的是哪一款？我帮您把两边的使用成本拉平看一下"）。
- **结论**：辩解会终结聊天，承认+反抛能把压价变成需求澄清。
- **结果**：同一句话，一版聊死一版续聊。（p142-143）

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这张卡？
1. 客户在微信上说"发个报价看看""各家都差不多，报个价"。
2. 客户说"你们偏贵""能不能再低点""别家比你们便宜 X"。
3. 纠结报价要不要留空间、要不要分几段报、要不要先讲价值再讲价格。
4. 报价发出去之后客户不回（需要判断是不是报价结构本身出了问题）。
5. 遇到明显没预算的客户，纠结要不要继续跟。

### 语言信号
- "客户要报价 / 怎么报 / 要不要留点空间"
- "客户说我们贵 / 让我再便宜点"
- "客户说别家更便宜"
- "客户只问价格，别的不关心"
- "客户没预算还要不要跟"
- "how to quote / they say we are expensive / can you lower the price"

### 与相邻能力的区分
- 与 **客户卡点诊断**：本卡解决"**怎么报**"，诊断卡解决"**报了没回应是什么状态**"。客户询价后消失 → 先走诊断卡判为三状态之一，若判为"纯比价"再回到本卡用两段低价法。
- 与 **三问验证**：本卡假设你已经知道该报给谁；如果连对方有没有采购权都没验证，先走三问验证。
- 与 **沟通与潜台词**：本卡管价格结构与让步的**时机**，沟通卡管这段话**怎么说**（例如"别在微信里一步步让价"）。压价话术的表达层在沟通卡。
- 与 **现场结账与关系维护**：★ **小恩小惠不是降价的替代品**。用送礼、请客来替代价格让步，会同时破坏两张卡（关系被物化，价格仍未解决）。
- 与 **跟进节奏与在场感**：报价后没回应不要靠加密度解决，先检查报法（见诊断卡与争议卡）。

## E — 可执行步骤 (Execution)

1. **先判客型与预算（决定要不要报、报什么结构）**
   - 动作：用两个问题给客户打标——① 他是否已在多渠道比价、把价格当入围门槛（询价客）？② 他的预算/消费能力是否真实存在（用途、规模、付费主体明确）？
   - 完成标准：产出一句"客户属于【询价客/需求待澄清客】+ 预算【真实/未知/不存在】"。
   - 判停条件：若预算不存在 → **不报价**，直接按无预算客户处理（第一圈筛掉），不要用低价去养；若客户是"需求待澄清客" → 先做需求澄清（转 `client-stuck-diagnosis` / `three-verifications`），不要急着报。

2. **报价：两段、第一段即真实底价、第二次让步不用价格**
   - 动作：给出两段报价，第一段就是你**真实能给的底价**（不虚高、不留空间）；同时准备一个"第二次让步"用的**非价格项**（交付时效、账号存活保障、发票、按量阶梯、账期）。
   - 完成标准：产出一份可直接发出的报价句子（含价格、含交付内容、含有效期），并写下"如果再让一次，我让的是哪个非价格项"。
   - 判停条件：若公司不授权你报低价、而客户又是纯询价客 → 明确承认这一单打不了价格战，转去抢下一个节点或做关系（不要用拖延话术应付）。

3. **被压价时算账，不降价**
   - 动作：把客户的"差价"换算成他的一次事故/一次返工/一段停机的代价，做成一张两行对比（差价 vs 损失），用一句话抛回。
   - 完成标准：产出一段可直接发出的算账话术，其中**至少一个数字是客户自己的**（他的规模、他的故障频率），不是我们产品的宣传数字。
   - 判停条件：若客户仍然只谈价格且不提供任何使用场景信息 → 判定为纯比价客，回到第 2 步给底价或放弃；不要继续投入话术成本。

## B — 边界 (Boundary) ★

### 不要在以下情况使用
- **客户还没说要买，你就报价**：报价是你最后一张牌，用在需求未澄清的客户身上只会变成被比价的靶子。
- **用关系投入替代价格让步**：送礼、请客、小恩小惠不能解决结构性价格问题（见 `relationship-settlement`）。
- **公司根本不授权价格**：此时本卡的"第一段即低价"无法执行，硬套只会让你给出无法兑现的承诺。

### 原文中警告的失败模式
- **把精力押在关系、人脉、低价上，自己不操盘**：把结果押在不可控变量上（反例 `cl-ce-07`）。
- **专业度不够**：同一个技术问题两次答不上、数据瞎编，价格再低也拿不到（反例 `cl-ce-26`）。
- **报价与利益表达失当**：报价绕弯子、把赚钱当罪过（反例 `cl-ce-49`；该条 V3 不过，属常识层，且内含源内时效冲突）。
- **"产品偏贵"时辩解**：辩解终结聊天，承认+反抛才续聊（p142-143）。

### 作者的盲点 / 时代局限
- **本卡直接建立在源内时效冲突之上**：作者在同一篇文章里推翻了自己早年"三段/四段报价、留非价格条款做交换"的教法。所以本卡给的是**2025 年的立场**，它的适用窗口是"客户信息透明 + 友商充分竞争 + 低价冲标"的环境；一旦环境回到供应稀缺、客户信息匮乏，旧法（先讲价值、留空间）仍可能有效。**详见 `conflicts/conflict-pricing-space.md`。**
- 原书的报价语境是**政企招投标**（标书、点位、技术先入围再比价）。使用者的代充业务是标准化商品、无标书流程、决策链短——"历史投标习惯"这类判据不可迁移，但"两段低价、不留空间、让客户自己加"的结构完全可迁移。
- 作者的经验断言（"90% 的客户说考虑一下就是价格问题""客户不理你 50% 是忙"）是修辞不是统计，只能当先验。
- 涉及**点位/控制点**的材料属合规红线（`cl-t-018`），只保留"资源只投控制点"的分析口径，**具体操作不进步骤**。

### 容易混淆的邻近方法论
- `client-stuck-diagnosis`：报法（本卡）vs 报了没回应的状态判断（诊断卡）。
- `communication-subtext`：价格结构（本卡）vs 压价话术的表达（沟通卡）。
- `relationship-settlement`：价格让步（本卡）vs 关系结算（结账卡）——两者不可互相替代。

### 来源之间的边界差异
- **源内时效冲突（必读）**：旧主张"三段/四段报价、最后留一个非价格条款跟客户做交换、做让步"（作者自述早年教法，p279）vs 新主张"两段报价、第一段即低价、不主动留空间"（p279-280）。作者本人的判断是旧法的前提已基本消失（"现在这时代就是低价冲标的时代"），因此**默认取新法**；旧法只在"客户需求尚未澄清、还没进入比价阶段"时保留使用。
- 完整分歧结构、双方证据与适用条件见 **`conflicts/conflict-pricing-space.md`**。
