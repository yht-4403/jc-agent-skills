# 逼单时机

## R — 原文 (Reading)

> "很多难事需要逼动客户去推动、去想透、去完成。……这跟关系好不好？没关系，这时候就是得逼客户。"
>
> — 广智,《广智的新手销售手册 2》· B2B 销售与客户逼单策略 · p39-40（source_id: src-a）

> "人的本性是，没有外力因素的情况下，人多半会选择原地不动……求上者得中，求中者得下……push 是要有筹码的……先学会浅浅地 push，这个 push 的前提是，你在技术服务，你在和他的私人交往……客户就都觉得很满意，然后你再去 push。"
>
> — 广智,《广智的新手销售手册 2》· 销售中的客户推动策略 · p226-228（source_id: src-a）

## I — 方法论骨架 (Interpretation)

有一类事客户**本能不会做**：向他的领导汇报、走内部流程、推动一个跨部门的决定。这类事的特点是——**跟他和你关系好不好无关**。关系再铁，他也倾向于原地不动，因为动了要担责任、要花精力、要面对内部摩擦。

所以销售必须充当那个**外力**。逼单不是态度问题，是结构问题：

1. **默认假设是"不动"**：人都选原地不动，所以"再等等"不是策略，等待只会让友商先动手。
2. **求上得中**：你开口要的越大，最后拿到的越多；只敢要一点点，往往连一点点都拿不到。所以要敢于把要求提上去。
3. **以进为退**：想拿当下的订单，不要直接催"这个月能签吗"，而是给出一个更大的方案（例如"明年整体打包+现在先启动"），让对方在比较中回头选那个你真正想要的选项。
4. **先有筹码，再浅浅地 push**：筹码不是话术，是**已经交付的技术服务和已有的私人交往满意度**。没有筹码就 push，等于一个三岁小孩威胁大人——不是被推动，是被拉黑。次序不能颠倒：先让客户满意，再浅浅地推一次。

配套一个"给客户理由"的动作：让客户在内部推进时有**能拿去加分的东西**（他向上汇报时的经营参与感、他个人的加 1 加 2）。你推的不是他的义务，是他的收益。

## A1 — 案例 (Past Application)

### 案例 1: 减肥训练营为什么火——劝不动，逼得动
- **问题**：为什么家人朋友反复规劝减肥都没用，训练营却有效？
- **方法论的使用**：作者用这个类比说明：关系好+口头规劝无法让客户完成难事，必须有一个**外部强制结构**。
- **结论**：难事靠外力，不靠感情。
- **结果**：逼单被重新定义为"提供那个外力"，而不是"施加压力"。（p40）

### 案例 2: 以进为退——明年订单换年前订单
- **问题**：想让客户赶紧下当前这笔订单，直接催容易被拒且没话接。
- **方法论的使用**：作者演示"以进为退"话术——先说想谈明年的整体合作，把局面做大，客户在权衡中反而回头先启动当前订单。
- **结论**：直接要小的容易断线，要大的反而拿到小的。
- **结果**：同一目标，用大方案包装后推进更顺。（p227）

### 案例 3: 邀约吃饭三遍话术（吹风 → 直接 → 羊腿烤上了）
- **问题**：客户不会主动答应你的邀约。
- **方法论的使用**：第一遍"有空一块吃个饭"只吹风（客户无法拒绝），第二遍直接约定，第三遍给一个具体的诱因（羊腿都烤上了）。
- **结论**：push 是**递进**的，一次比一次具体、一次比一次让步成本更低。
- **结果**：三遍之内把模糊意向变成具体安排。（p296-297）

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这张卡？
1. 已经确认客户认可你和产品，但他就是不去推动内部流程（不签、不报预算、不走审批）。
2. 客户一直说"我在推""我跟领导说了"，但一周两周没有任何动静。
3. 你知道客户内部有个节点（季度预算、年度采购、合同到期），想让他赶在这个节点前动作。
4. 想催但怕破坏关系，纠结要不要开口。
5. 已经在价格/方案上让步了，客户仍然不动。

### 语言信号
- "客户说在推，但一直没动静"
- "要不要催一下 / 催了会不会得罪他"
- "客户认可我们但不签"
- "怎么让客户去跟他领导说"
- "客户老是拖 / 说过几天再说"
- "how to push the client / they keep stalling / should I nudge them"

### 与相邻能力的区分
- 与 **客户卡点诊断**：本卡的前提是**已经知道阻力在哪**（或已确认是"客户本能不动"）；如果连是不是比价、有没有预算、对接人有没有权都不知道，先走诊断卡。
- 与 **跟进节奏与在场感**（★ 最易混）：跟进卡的"同一动作做三次"重复的是**你自己的出场**；本卡的"推"是**要求客户做一个动作**。把跟进卡用在逼客户推动流程上，会让客户觉得你在催命；把本卡用在还没建立在场感的客户身上，会被当成推销。
- 与 **三问验证**：本卡假设你押对了人；如果对接人根本推不动事，先回三问验证换人。
- 与 **报价与压价应对**：价格谈定之后的推进属本卡；价格未定时先走报价卡。
- 与 **领作业**：领作业是拿到"下一次见面的理由"（我方的下一步），本卡是让客户完成"他那边的难事"（对方的下一步）。
- 与 **脱敏与动作先行**：本卡解决"该推而不敢推"里的**策略**部分（怎么推）；如果你连消息都不敢发，先过脱敏卡。

## E — 可执行步骤 (Execution)

1. **先诊断阻力，别等也别空催**
   - 动作：用一句话给客户的"不动"归因——是**不知道该怎么做**（缺路径）、**不敢做**（要担责）、还是**不急**（没有时间压力）？分别对应：给路径、给免责素材、给时间锚。
   - 完成标准：产出一句"客户不动的原因是【缺路径/怕担责/没紧迫感】，我要给的是【一份可转发材料/一个免责说法/一个时间锚】"。
   - 判停条件：若归因不出来 → 先做一次验证性提问（问一个他必须回答的具体问题），不要直接催。

2. **确认筹码，再决定推不推**
   - 动作：检查推的前提是否成立——① 技术服务上有没有已交付的东西（让他觉得你专业）；② 私人交往上有没有基本满意度（他会愿意接你的话）。两条都不成立时，先补筹码（转 `followup-rhythm` / `relationship-settlement`）。
   - 完成标准：写出"我的筹码是：<一项技术支持> + <一次已建立的好印象>"。
   - 判停条件：**无筹码不硬 push**——硬推的结果不是被推动就是被拉黑（材料池反例 `cl-ce-67`）。

3. **推一次，给路径、给材料、给时间锚**
   - 动作：只发一个**可以被他直接转发**的东西（一页纸对比、一句可直接引用的话、一份内部汇报素材），并附一个明确时间锚（"这个季度预算报批是 X 号之前吧？"）。不要同时提多个要求。
   - 完成标准：产出可直接发出的那段话 + 它替客户省掉的具体动作（他只需要转发/只需要说一句话）。
   - 判停条件：**推三次仍不动 → 回去搞清原因再绕道**（绕的是路径，不是关系）。若三次之后原因是"他确实推不动"，转 `three-verifications` 换人；若是"他没紧迫感"，转时间锚设计；**不要原地死磕**。

## B — 边界 (Boundary) ★

### 不要在以下情况使用
- **筹码未建立时**：客户还没认可你的专业与为人，此时 push 只会加速出局。
- **对接人根本推不动事**：这不是逼单问题，是押错人（转 `three-verifications`）。
- **客户明确表达了客观困难**（组织变动、预算冻结、家里有事）：此时该做关怀减压（转 `relationship-settlement`），逼单会显得冷血。

### 原文中警告的失败模式
- **只等和催，不诊断阻力**：绝大多数人选择"等等客户"，等来的只有恶化——友商也在催也在等（反例 `cl-ce-63`）。
- **只靠关系不逼**：难事上客户本能不动，关系好不等于会推进（反例 `cl-ce-66`）。
- **无筹码硬 push**：没有筹码就施加压力，结果是"不是被推动就是被拉黑"（反例 `cl-ce-67`）。

### 作者的盲点 / 时代局限
- **★ D7 边界（必读，最易误用）**：本卡的"推三次不动就绕道"**不等于放弃客户**——原文紧接着要求"搞清楚原因后绕道走"，绕的是**路径**而不是关系。同时**不许**把 `followup-rhythm` 的"重复触达法则（同一动作做三次）"当成逼单方法：那条重复的是你的出场，不是要求客户办事。（见 `verdicts/DECISIONS.md` D7）
- **"加 1 加 2"与"经营参与感"是体制内语汇**：它们依赖客户有明确的职级晋升与内部汇报体系。使用者的线上代充客户（中小客户、技术对接人、采购）多半没有这套结构，迁移时应改成"给他一份能在群里/会上直接用的材料"这类通用收益。
- 原书语境是**线下政企**（带队考察、走流程、饭局）。线上业务的"难事"更多是"把续费审批推上去""在群里确认预算"，push 的载体必须换成线上可用的材料与时间锚，不要照搬饭局邀约。
- 整套方法假设"客户个人能影响采购结果"。在集体决策、强合规的自助采购环境里，push 个人是无效的——此时唯一的杠杆是价格与产品本身。

### 容易混淆的邻近方法论
- `followup-rhythm`：重复自己的出场（跟进卡）vs 要求客户做动作（本卡）。
- `client-stuck-diagnosis`：还不知道阻力在哪（诊断卡）vs 已知阻力需要外力（本卡）。
- `next-step-assignment`：拿我方的下一步理由（领作业）vs 推进对方的下一步（本卡）。

### 来源之间的边界差异
- 无源间分歧。但同一"必须推"的立场有两层表述密度：p39-40 是**立场总纲**（难事必须逼、与关系无关），p226-228 是**技术细则**（筹码、求上得中、以进为退）。两层不冲突：先满足细则里的筹码前提，再执行总纲的"必须推"。
