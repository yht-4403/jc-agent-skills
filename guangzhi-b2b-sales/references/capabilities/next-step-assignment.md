# 领作业

## R — 原文 (Reading)

> "拜访的核心是什么呢？我称之为三个字叫领作业……你以后策划任何拜访的时候，你最重要的事儿是什么？就是怎么能和人家再见到面……就是我们要找理由和人家再见面，那找什么理由？就是领作业。"
>

>
> — 广智,《广智的新手销售手册 2》· 技术交流别白忙：要有明确结论 · p218-221（source_id: src-a）

>

## I — 方法论骨架 (Interpretation)

每一次接触客户，都要拿到一个**下次再见面的理由**。这个理由在作者那里叫"作业"，它是一个**许可（permission）**，不是任务（task）——不是客户布置给你一份活儿，而是客户同意"下次我们为了某件事再谈"。

判断一次接触是否合格，不看聊得好不好，看有没有产出下面任一项：

- 一个具体的待办（报价、方案细化、技术答疑、参数确认）；
- 一个约定的时间（下次对齐的时间点）；
- 一个引进来的角色（对接人、技术、领导、拉群）。

这套判据也适用于技术交流：一场**没有结论**的技术交流等于没发生，需要再补一场。所谓有结论，指的是拿到了对接人、时间、可验证的试用计划、愿意监督的领导，或者进了群——**不是**客户当场说"挺好""有需要联系你"。

配套两条执行规则：

1. **把场面话固化成事项，并定量约定**。客户说"再研究研究"不是结论；要翻译成"这件事我们一个月内做，我每周找您对一次进度"（作者给的经验频率是一周两次）。
2. **事先用倒推法盘点资源**：拿到线索先假设"已经中标"，再倒推中标需要哪些条件（高层定调、中低层配合、资源与人脉），把差距列出来去补——而不是走一步看一步。

## A1 — 案例 (Past Application)

### 案例 1: 客户说不考虑替换，照样领到作业
- **问题**：客户已有供应商、明确说"暂时不考虑替换"（作者形容为"不缺人追的男神女神"）。
- **方法论的使用**：不推销替换，而是就着对方现有方案提一个**具体的比较问题**（在什么场景下现有方案会吃力），把话题转成一个待办。
- **结论**：客户拒绝"被推销"，但不拒绝"回答一个具体问题"。
- **结果**：拿到了下一次接触的理由（p216-217）。

### 案例 2: 地推重卡博主的第一视角视频
- **问题**：怎么从门卫一路见到老板而不被挡。
- **方法论的使用**：作者刷到一位地推博主的第一视角视频——每次被挡都换一个具体的由头（找人、送资料、问一句事），松弛且不纠缠。
- **结论**：领作业的关键不是话术华丽，而是**每次都有一个具体的、对方能接的由头**。
- **结果**：作者把它作为胆量与松弛感的示范（p215-216）。

### 案例 3: 「方案已整理好」式推进
- **问题**：客户答应帮忙推进，销售想催又不想显得在催。
- **方法论的使用**：不带"进度怎么样了"的空问法，而是带产出推进——"方案我已经整理好了，需要您给我两份资料，另外想约这周一次 15 分钟"。
- **结论**：推进的正确形态是**给产出 + 提具体请求**，不是问进度。
- **结果**：客户有事可做、有物可回，接触不落空（p17）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这张卡？
1. 一次沟通/拜访结束，感觉聊得不错，但不知道下一步干什么。
2. 客户说"再研究研究""有需要联系你"，你想把它变成一个有日期的待办。
3. 客户答应了帮忙推进，但之后没有下文，你又不想纯催进度。
4. 需要跟客户做一次技术/产品说明，想确保这次说明不白做。
5. 准备约下一次接触，但找不到自然由头。

### 语言信号
- "聊完了下一步该干什么 / 怎么约下一次"
- "客户说再研究研究 / 有需要联系你"
- "客户答应了但没动静"
- "这次技术交流怎么才不算白做"
- "怎么找个理由再联系他"
- "what's the next step / how to book the next meeting / how to follow up with a purpose"

### 与相邻能力的区分
- 与 **跟进节奏与在场感**：本卡管"**这次接触要拿到什么**"（一个理由），跟进卡管"**多久接触一次**"（频率）。同一次接触里两者同时成立：先排节奏（跟进卡），再保证每次都有作业产出（本卡）。
- 与 **逼单时机**：本卡要的是"我方的下一步许可"（我下次能再来谈什么），逼单卡要的是"对方的下一步动作"（他去推内部流程）。一个是 permission，一个是 action。
- 与 **沟通与潜台词**：本卡是**结构化产出**（对接人/时间/待办/拉群），沟通卡是**单句表达与解读**。沟通不落地时用本卡补产出，表达不对时用沟通卡改说法。
- 与 **客户卡点诊断**：诊断卡在接触**之前**判断状态（值不值得投入、卡在哪），本卡在接触**之中**保证产出。
- 与 **三问验证**：三问验证判"这个客户/这个人值不值得"，本卡判"这次接触有没有收获"。

## E — 可执行步骤 (Execution)

1. **接触前：先定这次要领什么作业**
   - 动作：写下一句话——"这次接触，我希望拿到【一个待办 / 一个时间 / 一个引进的角色】中的哪一个"，并准备对应的**具体由头**（不是"关心一下"，而是一个真实存在的问题或待确认的细节）。
   - 完成标准：产出"由头 + 想要的作业类型"两行字；由头必须能被对方用一句话回答。
   - 判停条件：若连由头都写不出来 → 这次接触先别约（转 `client-stuck-diagnosis` 判断客户状态）。

2. **接触中：把结论做实，用四件套检查**
   - 动作：结束前对照检查是否拿到——**对接人、时间、可验证的下一步（试用/报价/参数）、群或监督人** 四件套中的至少一项；用一句明确的话把结论说出来（"那我们下周三之前把参数确认了，我拉个群"）。
   - 完成标准：产出"本次结论：<四件套中拿到的项>；无结论项：<缺哪项>"。
   - 判停条件：若四件套一项都没拿到 → 明确判定"本次无结论"，**当场再约一次**（约一个具体时间或具体由头），否则这次接触等于白做。

3. **接触后：把场面话固化成事项并定量约定**
   - 动作：24 小时内发一条消息，把本次结论写成"事项 + 频率 + 时间点"（例：参数确认这件事一个月内推完，我每周三找您对一次），并在自己的日历上排好这两次跟进。
   - 完成标准：产出一条已发出的消息 + 日历上至少两次已排定的跟进。
   - 判停条件：若客户回复模糊、不接频率约定 → 回到本卡第 1 步换由头，或转 `client-stuck-diagnosis` 判状态；不要靠反复追问进度填空。

## B — 边界 (Boundary) ★

### 不要在以下情况使用
- **用微信文字去要"作业"**：需要客户做判断的请求（要资料、要引荐、要拍板）在文字里等于让客户写作文，且完全被动（材料池反例 `cl-ce-01`）。此时应换电话/会议。
- **请求本身不可执行**：像"帮我替换掉旧供应商"这种模糊请求，客户无从下手（反例 `cl-ce-03`）。
- **上一次的账还没结**：麻烦客户之前先确认上一次已经给了回报（反例 `cl-ce-04`），否则要作业会变成索取。
- **只能靠组织资源才能推进的项目**：独立作战、不调用公司资源，会让"领作业"变成你个人的硬扛（反例 `cl-ce-18`，该条 V1 单处、锚点质量偏低）。

### 原文中警告的失败模式
- **把"聊得好"当结论**：客户"上头"只能维持半天到一天，没有四件套就等于没有结论（p218-221）。
- **只问进度不给产出**："进度怎么样了"是最容易被敷衍的问法，正确形态是带产出 + 提具体请求（p17）。
- **把时间花在开场话术上**：作者明确反对——拜访的核心不是开场设计，而是能不能再见面（p215-218）。

### 作者的盲点 / 时代局限
- **⚠️ 术语陷阱（必读）**：本卡的"作业"是**你向客户领的许可（permission）**，不是客户布置给你的任务（task）。作者在同一篇里用"作业"指代过两个方向的概念（另见术语层的"作业（客户布置的）"），**不要把本卡理解成"被动接活"**（见 `verdicts/DECISIONS.md` D8）。
- **线下载体不可照搬**：原书的领作业发生在**登门拜访**里（门卫、前台、老板、会议室）。使用者的接触发生在**微信与线上会议**，所以"四件套"的形式要迁移（拉群、约线上会、要一份具体清单），不要强行约见面。
- 原书的"高层定调、中低层配合、打控制"属政企操盘语汇，其中"打控制"涉及合规红线（点位/控制点），**只保留"资源盘点与差距弥补"的思维，不保留其操作**。
- 作者的定量断言（"一周沟通两次""做三遍成功率高 30–50%"）是经验值，不是统计。

### 容易混淆的邻近方法论
- `followup-rhythm`：本次拿到什么（本卡）vs 多久接触一次（跟进卡）。
- `push-timing`：拿许可（本卡）vs 推客户做动作（逼单卡）。
- `relationship-settlement`：拿理由（本卡）vs 给回报（结账卡）——同一次接触里两者要配对，不能只拿不给。

### 来源之间的边界差异
- 无源间分歧。"领作业"这个判据在 p73 与 p215-218 两处独立出现，前者谈**预期管理**（拜访最好结果就是能再拜访），后者谈**开局设计**（策划任何拜访时最重要的事），两者互补：本卡取"必须拿到理由"这一共同结论，不取任一处的具体话术模板。
