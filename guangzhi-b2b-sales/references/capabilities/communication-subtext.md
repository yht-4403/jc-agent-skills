## I — 方法论骨架 (Interpretation)

微信是使用者的主战场（绝大多数客户沟通发生在微信群里），而微信这个通道本身有两个结构性缺陷：**它让客户可以不回**（你完全被动），**它逼客户读长文做判断**（等于让客户写作文）。所以沟通的第一层纪律不是"话术好不好听"，而是**别把需要客户思考、判断、承担风险的事放进微信文字里**。

三条通道纪律：

1. **该升通道就升**：文字交流控制在 20–30 句内，超过就升级为电话或会议——三五分钟电话能说清的事，不要在微信耗半小时。重要求助、需要客户做判断的提问，一开始就不要发微信。
2. **让对方有选择权**：说服的前提是"给对方不听你说服的权利"。宣讲别太满，给客户留出拒绝的空间，他反而更容易靠近。
3. **问有信息量的问题**：零信息量的大话（"这项目我们能做吗""还需要你多照顾"）不是沟通，是自我安慰——它把判断成本推给客户，客户只能不回。

第二层是**自己的可读性**：自我介绍要素齐全（姓名/公司/家乡/工龄/服务过的客户）且对谁都敢完整说；能讲清自己相对竞对的优劣（客户会接触 5–10 家对手，比你还懂市场）；礼貌真实（面无表情客户就接收不到热情）；称呼随关系亲近但要稳定，不要忽冷忽热。

第三层才是**听**。「潜台词识别法」主张：客户话语中约九成是粉饰性客套，要剥离情绪态度词、抓话语里的动词，推断真实动作（推进/拖延/拒绝/求助）。⚠️ **这条技术在本书中只出现过一处（p20-21），属单一来源、未经其他章节印证**，使用时把它当"提问清单"而不是"判据"（详见 B 段与审计信息）。

## A1 — 案例 (Past Application)

### 案例 1: 作者以买方身份亲历——被加微信的销售淹没
- **问题**：作者在自己企业做采购时，被大量销售加微信。
- **方法论的使用**：他站在客户一侧记录：买方同时面对这么多销售，微信文字根本不会被认真读完。
- **结论**：微信不是"低成本触达"，而是"高竞争、低注意力"的通道。
- **结果**：这条亲身观察支撑了"重要事必须升通道"的纪律。（p45）

### 案例 2: 问「你有孩子了吗」踩雷 vs 先自报再问籍贯
- **问题**：想用家常话题拉近关系，一开口就问客户私事，客户直接冷掉。
- **方法论的使用**：对照两版——错误版上来就问"哥你有孩子了吗"；正确版先自报"我漠河的"再问对方籍贯。
- **结论**：提问的信息量与自报比例决定客户愿不愿意接话。
- **结果**：同一话题，先给信息再提问的那版能聊下去。（p112 / p143）

### 案例 3: 助贷冷电话的两种开场
- **问题**：电话拓客时开场没人愿意听下去。
- **方法论的使用**：错误版开口"贷款需要吗"，客户反问年息就答不上；正确版第一句就完成价值投递。
- **结论**：开场不是打招呼，是"一句话把价值和一个可继续的问题同时给出"。
- **结果**：错误版被 2 秒挂断，正确版能进入下一轮。（p210）

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这张卡？
1. 要在微信上跟客户说一件重要的事（催进度、要信息、说明涨价/调价、拒绝需求）。
2. 客户在微信上回得越来越短（"好的""收到""再看看"），想判断他到底什么意思。
3. 要问客户一个可能让他为难的问题，纠结该不该发微信还是打电话。
4. 想自我介绍或说明自己的优势，但总觉得说出来像自夸。
5. 客户群里气氛冷掉、问什么都不接。

### 语言信号
- "这句话怎么回 / 我该怎么跟他说"
- "客户回了个'好的'就不理我了，他什么意思"
- "要不要直接打电话给他 / 微信上问合不合适"
- "怎么跟客户说涨价 / 怎么拒绝他这个要求"
- "客户在群里不回我"
- "how should I reply / what does he mean by that / should I call instead of texting"

### 与相邻能力的区分
- 与 **客户卡点诊断**：本卡解**一句话/一段对话**的真意与答法（微观）；诊断卡用**客户做过的动作**判状态（宏观）。只有单句判读走本卡；整段时间没动作走诊断卡。
- 与 **跟进节奏与在场感**：本卡管"这一次怎么说"，跟进卡管"多久说一次、怎么保持在场"。同一句"客户不回我"若已确认是密度问题 → 转跟进卡。
- 与 **报价与压价应对**：报价怎么说、压价怎么接走报价卡；本卡只管渠道与表达方式（例如"别在微信里一步步让价"）。
- 与 **领作业**：本卡不负责"要到下一次见面的理由"，那是领作业卡；本卡负责让这次沟通不被误读。
- 与 **脱敏与动作先行**：本卡治"说得不对"，脱敏卡治"不敢说"。发出去之前反复纠结到不敢发 → 脱敏卡。
- 与 **现场结账与关系维护**：本卡管信息层沟通，结账卡管利益与回报的结算动作。

## E — 可执行步骤 (Execution)

1. **先分通道：这条消息该不该用微信发**
   - 动作：判断这条内容是否要求客户"思考、判断、承担风险"（要钱、要决定、要他去内部推）。是 → 改电话/会议；否（信息同步、进度汇报、确认时间）→ 可用微信，但**数句子**。
   - 完成标准：产出一句"这条走【微信/电话/会议】，预计往返 X 句"。
   - 判停条件：若这条是求助或需要客户做判断的提问 → 直接跳到第 3 步，不要用微信发（微信求助=自杀式）。

2. **再改文字：给动作、给选择、去零信息量**
   - 动作：把消息重写成"**一个具体动作 + 一个明确选项 + 一句自报信息**"。删掉所有"多照顾""能不能做""您看方便吗"这类零信息量句；保留一个客户可以拒绝的出口（选择权）。
   - 完成标准：改写后的消息里能指出——客户读完只需要回一个词或一个时间；且有一条是"我这边已经做了什么"。
   - 判停条件：若改写后超过 30 句仍未说清 → 说明这事不该用文字说，回到第 1 步升通道。

3. **最后听回音：用动作对账，不用情绪对账**
   - 动作：客户回复后，只记录**动作类信息**（给了人、给了时间、给了数字、问了细节），把"好的/收到/再看看"这类情绪词单独列、不当结论。若连续两次往来没有任何动作类信息 → 判定为需要状态诊断，转 `client-stuck-diagnosis`。
   - 完成标准：产出"本轮客户动作：<列出的动作或无>；下一步动作：<一条>"。
   - 判停条件：若客户给的是明确拒绝（不需要/已定别家）→ 停止推进，不要继续"改善表达"。

## B — 边界 (Boundary) ★

### 不要在以下情况使用
- 客户已明确拒绝或已用友商：这不是表达问题，继续优化话术会变成纠缠。
- 问题根源在报价结构或项目状态（客户因为价格或流程而不回）：本卡只能让你说得更清楚，救不了错误的价格（转 `pricing-response` / `three-verifications`）。
- 你还没准备好要说什么：本卡会给你的输出设"必须有动作和选项"的门槛，缺料时先回材料，不要硬凑。

### 原文中警告的失败模式
- **文字渠道误用**：把微信当求助/提问/长文通道（材料池反例 `cl-ce-01`）——文字缺紧迫感、留痕让客户更谨慎、且完全被动。
- **半截子渠道**：用电话做即时索取，客户两秒内挂断或给个模糊承诺（反例 `cl-ce-02`）。
- **背话术的机器人**：状态与生命力缺失，同一套词从电话搬到微信都失效（反例 `cl-ce-29`）。
- **线上人格载体缺失**：头像与昵称无法检索、不可识别，客户记不住你是谁（反例 `cl-ce-30`）。
- **拿客户练表达**：一天拜访最多 40 分钟说话量，绝不是练说话的场合（p91/p204）。

### 作者的盲点 / 时代局限
- 原书的"当面/电话优先"建立在**线下政企**语境（能见面、能上门）。使用者做线上代充，客户分散、决策链短，**不可能事事打电话**——所以"升级通道"要用"线上可用的升级"替代：语音条、短会、明确的时间锚，而不是强行约见面。
- 作者的"90% 客户话语是粉饰"是**经验修辞不是统计**（OVERVIEW 批判段第 3 条）。把它当判据会导致过度解读——客户说"再考虑一下"也可能真的是要再考虑。
- **⚠️ 潜台词识别法是单一来源**（仅 p20-21 一处，无第二章节复述）。按分级纪律它只能作技术示例，不能作本卡的判据主干；使用者应把它当"提问清单"，用后续对话去验证，而不是直接下判断。

### 容易混淆的邻近方法论
- `client-stuck-diagnosis`：单句真意（本卡）vs 整段行为证据（诊断卡）。
- `followup-rhythm`：怎么说（本卡）vs 多久说一次（跟进卡）。
- `desensitize-action-first`：说得不对（本卡）vs 不敢说（脱敏卡）。

### 来源之间的边界差异
- 与**报价**相关：作者强调"不要主动给客户留空间、不要在微信里一步步让价"，这与 `conflicts/conflict-pricing-space.md` 里的新法一致；若使用者沿用旧的三段留空间做法，则本卡的微信纪律会与报价策略冲突——两卡同时触发时以报价卡的争议结论为准。
