# 客户卡点诊断

## R — 原文 (Reading)

> "第一个叫角色的权限不足……第二个就是你问的事儿涉及到领导，涉及到内部的博弈……第三个竞争对手已经锁定了……第四个信任没有达到阈值……第五个项目的真实性存疑……第六个就是个人利益未满足。"
>
> — 广智,《广智的新手销售手册 2》· 客户不回答问题？原因与应对 · p110-112（source_id: src-a）

> "客户问两句就走了，他处于什么场景？我认为就只有三点。第一点就是他可能买，但是他不确定自己要不要买……第二种情况是出来询价……第三种情况，就是他和厂家已经交流的差不多了，出来看看其他厂家的方案怎么样，心里有个安慰。"
>
> — 广智,《广智的新手销售手册 2》· 客户询价后无回应的应对策略 · p239-240（source_id: src-a）

## I — 方法论骨架 (Interpretation)

客户不回、不理、让等、询价后消失，这四种现象背后至少有九种完全不同的状态。把它们当成"客户不喜欢我"或"客户在忙"来猜，是最常见的两个误判——前者自作多情，后者自我安慰。

正确的顺序是**先定状态，再选动作**。判据不是客户的情绪词（"好的""再看看""挺感兴趣"），而是客户做过的**动作**：有没有给你具体问题、有没有引荐第二个人、有没有问价格细节、有没有谈交付时间。动作指向状态，状态决定你该做什么。

诊断分两条入口：

- **对话型卡点**（不回、不理、让等）：走六因表——权限不足、涉及内部博弈、友商已锁定、信任未到阈值、项目真实性存疑、个人利益未满足。六因互不覆盖，命中哪一条，动作完全不同：权限不足要换人，内部博弈要提供"能拿去汇报的材料"，友商锁定要抢下一个节点，信任不足要加密度而不是加话术。
- **比价型卡点**（询价后无回应）：只走三状态——不确定要不要买、纯比价、已定友商求安慰。第一种值得投入（帮他定义需求），第二种不要投入话术（直接给真实低价，见"报价与压价应对"），第三种不要争单（转为长期关系维护）。

## A1 — 案例 (Past Application)

### 案例 1: 年长客户的冷淡不是针对你
- **问题**：客户态度冷淡、不接受应酬，销售以为自己哪里做错了。
- **方法论的使用**：作者把"冷淡"这个情绪表现，换成对客户身体状态的判断——年长客户受疾病与睡眠影响。
- **结论**：这是**客户状态**问题，不是**对你态度**问题。
- **结果**：不必消耗在自我怀疑上，动作照常推进、降低应酬强度即可。（p24-25）

### 案例 2: 私企老板第一通电话的不耐烦
- **问题**：首通电话客户语气烦躁，销售判定"这客户没戏"。
- **方法论的使用**：作者归因到客户在加班、被频繁打扰，而非拒绝这个供应商。
- **结论**：首通电话的情绪不构成状态判据，需要第二次接触才谈得上判断。
- **结果**：避免用第一通电话的情绪给客户判死刑。（p25）

### 案例 3: 装修全程不参与，装好了也不满意
- **问题**：为什么交付都做完了，客户还是不满意？
- **方法论的使用**：作者用装修类比——客户一天没看过设计稿、没参与决策。
- **结论**：客户要的不只是结果，还有**参与感**；"不参与"本身就是一种卡点状态。
- **结果**：把过程汇报设计成客户的参与动作（每阶段留一个需要他拍板的点），不满意率下降。（p95-96 / p173）

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这张卡？
1. 客户在微信上不回消息、已读不回、或者只回"好的""收到"之后就没下文。
2. 报价/方案发出去之后，客户既不还价也不说不做，直接消失。
3. 客户一直说"再等等""在走流程""上面还没批"，但没有任何可验证的进展。
4. 客户态度忽冷忽热，想判断是自己哪句话说错了还是客户那边有事。
5. 跟进多次无果，纠结"还要不要继续跟"。

### 语言信号
- "客户好几天不回了 / 已读不回 / 发消息不回我"
- "报价发过去就没动静了 / 客户说要考虑一下就没下文了"
- "客户一直让我等 / 说在走流程 / 说领导还没批"
- "这个客户是不是对我有意见 / 是不是不想理我"
- "还要不要继续跟这个客户"
- "client ghosted me / no reply / should I keep following up / they keep stalling"

### 与相邻能力的区分
- 与 **跟进节奏与在场感**：本卡先回答"**是什么状态**"，跟进卡回答"**多久跟一次、怎么保持在场**"。同一句"客户不回我"，先走本卡定状态；定完状态若结论是"没被忘，只是密度不够"，才转跟进卡。
- 与 **逼单时机**：本卡处理"客户不动但方向未明"，逼单卡处理"已经确认卡点、客户本能不动、需要推他一把"。客户说"在走流程"若已确认是真实流程卡点 → 转逼单卡；若连流程真假都不确定 → 留在本卡。
- 与 **沟通与潜台词**：本卡用的是客户**做过的动作**（宏观行为证据），沟通卡解的是**一句话里的真意**（微观语言证据）。客户只回"好的"这种单句判读走沟通卡；整段往来没动作走本卡。
- 与 **报价与压价应对**：卡点若诊断为"纯比价"，本卡给结论，报价卡给报法（两段低价法与不留空间的争议边界）。本卡不做报价设计。
- 与 **三问验证**：本卡诊断"当下为什么不动"，三问卡诊断"值不值得投入"（职权/性格经验/项目状态）。已投入很多才发现押错人，是三问卡漏做的结果。
- 与 **脱敏与动作先行**：客户不回若判定为**策略问题**（比价/友商锁定/权限不足），本卡有效、脱敏卡无效；只有在判定为"你不敢发消息"时才归脱敏卡。

## E — 可执行步骤 (Execution)

1. **把卡点归形态，给出一个标签**
   - 动作：把最近一段客户往来（微信/邮件）过一遍，只记录客户**做过的动作**（问了什么、给了谁、提没提钱和时间），把情绪词全部划掉。然后归入四形态之一：不回 / 不理人 / 让等 / 询价后无回应。
   - 完成标准：产出一句话，形如"客户属于【让等】形态，近 3 次往来里客户的动作只有『说在走流程』"。
   - 判停条件：如果发现客户其实给过具体问题或引荐过人 → 不是卡点，回到正常推进，不套本卡。

2. **按形态走诊断表，落一个状态结论（并写下依据）**
   - 动作：让等/不回/不理 → 走**六因表**逐条排查（权限不足 / 内部博弈 / 友商锁定 / 信任未到阈值 / 项目真实性存疑 / 个人利益未满足）；询价后无回应 → 走**三状态**（不确定要不要买 / 纯比价 / 已定友商求安慰）。
   - 完成标准：产出一句"状态结论 + 一条可验证依据"，形如"判断为【权限不足】：他三次都答不了价格与合同条款，需要换能定事的人"。
   - 判停条件：若两条依据互相矛盾、无法落一个状态 → 本步不硬判，直接进第 3 步做"验证性动作"，用一次接触换答案。

3. **按状态选一个动作，且只选一个**
   - 动作：从状态→动作映射里选唯一动作并写出来：
     - 权限不足 → 找能定事的人，或请现对接人做引荐动作（不是请他"帮忙推"）；
     - 内部博弈 → 提供他能拿去内部汇报的材料（一页纸、对比表、可引用的数据）；
     - 友商已锁定 → 停止抢单，改抢下一个节点/下一轮，转入关系维护；
     - 信任未到阈值 → 加密接触频率（转跟进卡），不加话术长度；
     - 项目真实性存疑 → 先验证项目是否存在（转三问卡）；
     - 个人利益未满足 → 识别他真正的个人诉求，不做越线承诺；
     - 询价-不确定买不买 → 帮他定义需求，再谈方案；
     - 询价-纯比价 → 转报价卡，直接给真实低价；
     - 询价-已定友商求安慰 → 转关系维护卡，不争这一单；
     - 参与感缺失（让等的常见成因）→ 每阶段留一个需要客户拍板的决策点。
   - 完成标准：产出一条**可以直接发出去**的消息或一个明确的下一步动作（含时间），并写清"我判断这条动作对应哪个状态"。
   - 判停条件：若动作依赖尚未确认的事实（如是否有采购权），先发"验证性动作"（一问一答式、短、给选项），下次再定。

## B — 边界 (Boundary) ★

### 不要在以下情况使用
- 客户已经明确说"不需要/不做了/已经用了别家"——这是结论不是卡点，继续诊断会变成骚扰。
- 客户纯粹是渠道噪音（从没给过任何具体回应、也无从验证需求真实性），应转三问验证判断是否值得投入，而不是诊断"为什么不回"。
- 自己不敢发消息、发完就焦虑——那是心态问题（转脱敏与动作先行），诊断表能给你答案但你不会去执行。

### 原文中警告的失败模式
- **自作多情型误判**：把客户的忙读成"讨厌我"，把客户的情绪读成"对我有意见"（材料池反例：老年客户因健康不应酬、私企老板因加班不耐烦）。
- **因果倒置型误判**：为做关系而做关系，把精力押在关系、人脉、低价上，自己不操盘项目（材料池反例 cl-ce-06 / cl-ce-07）。
- **文字渠道误用**：拿微信去问需要客户思考与承担判断风险的问题，等于让客户写作文；客户不回有时不是状态问题，是你的通道选错了（转沟通与潜台词）。
- **请求不可执行**：像"帮我替换掉旧供应商"这种模糊求助，客户无从下手，于是"不回"（材料池反例 cl-ce-03）。

### 作者的盲点 / 时代局限
- 原书主场景是**线下政企关系型销售**（拜访、饭局、标书、点位）。使用者做线上 ChatGPT 账号代充，客户在微信群、决策链短、采购流程轻——"六因表"里"内部博弈""项目真实性存疑"的出现频率会显著低于原书语境，而"比价""已定友商"的频率会更高。**不要照搬六因的排查顺序**。
- 作者的量化断言（"客户不理你 50% 是忙""说考虑一下 90% 是价格问题"）是**经验修辞，不是统计**（OVERVIEW 批判段第 3 条）。只能当"先假设、快验证"的先验，不得作为判据。
- 整套方法假设"客户个人有自由裁量且可被个人关系影响"。在集体决策、强合规、线上自助采购的环境里，六因里的"个人利益未满足"这条几乎没有操作空间。

### 容易混淆的邻近方法论
- `followup-rhythm`：定状态 vs 定频率。
- `push-timing`：已确认卡点后推他一把 vs 还不知道卡点在哪。
- `communication-subtext`：单句真意 vs 整段行为证据。
- `pricing-response`：比价结论之后的报法。
- `three-verifications`：值不值得投入 vs 当下为什么不动。

### 来源之间的边界差异
- 与 **报价结构**有关：客户"询价后无回应"里的"纯比价"分支，其应对方式直接受 `conflicts/conflict-pricing-space.md` 约束（作者 2025 年推翻了自己早年的三段留空间报价法）。本卡只负责判定"他是纯比价"，报法交报价卡。
