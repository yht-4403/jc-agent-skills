# v5 原子拆分指南

## 来源边界

本指南借鉴 DBS 内容工程里的「问题、概念、观点、案例、方案」单元，但不是 DBS 原作者规定的成稿模板。

v5 的处理逻辑是：

1. 先把知识库长文拆成内容原子。
2. 再从原子中选一个最适合小红书的问题。
3. 如果问题、概念或角度不稳，再进入自动路由。
4. 最后只围绕一个问题装配正文。

不为了匹配作者身份、账号定位或发布渠道新增例子。不要把原文主题迁移到无关行业、个人经历或个人复盘。

## 五类原子

### 1. 问题单元 Q

定义：读者正在经历的、能被一句话说清楚的具体问题。

合格格式：

```text
[Q1] 当 [人群] 遇到 [具体场景] 时，为什么会 [错误动作/卡点/损失]？
```

不合格：

- 「解决方案能力很重要」
- 「销售新人如何成长」
- 「如何提高商业认知」

这些太大，不能直接成稿。

### 2. 概念单元 C

定义：原文里承担解释重量、但容易被误解的大词。

每个概念必须写：

```text
[C1] 概念名：原文里指什么；大白话怎么说；成稿中保留/替换/解释/删除；风险等级低/中/高。
```

风险等级：

- 低：只是表达包装，去掉也能讲清楚。
- 中：不同读者可能理解不同，首次出现要解释。
- 高：去掉后文章就说不清楚，必须进概念门判断是否调用 `dbs-deconstruct`。

### 3. 观点单元 O

定义：作者真正想表达的判断。

合格格式：

```text
[O1] 在 [边界] 下，[判断]，因为 [机制]。
```

注意：

- 观点不能脱离边界。
- 没有机制的观点只能当素材，不能当正文主轴。
- AI 推断必须标注，不写成事实。

### 4. 案例单元 E

定义：一个具体场景、对话、行为、数字、反馈。

合格格式：

```text
[E1] 场景：[谁] 在 [什么时候] 做了 [什么]，结果/信号是 [什么]。
```

优先级：

1. 真实对话
2. 具体行为
3. 数字或反馈
4. 有前后变化的案例
5. 抽象例子

### 5. 方案单元 S

定义：读者下一次能做的动作。

合格格式：

```text
[S1] 下次遇到 [场景]，先做 [动作 1]，再确认 [动作 2]，最后争取 [动作 3]。
```

不合格：

- 「提升认知」
- 「增强方案能力」
- 「多关注客户需求」

这些是愿望，不是动作。

## 选题评分

每个问题单元按 1-5 分打分：

| 维度 | 5 分标准 |
|---|---|
| 痛点即时性 | 目标读者看第一眼就知道说的是自己 |
| 冲突强度 | 常见做法和正确判断明显相反 |
| 场景具体度 | 有可视化场景、对话或动作 |
| 材料可支撑度 | 有概念、观点、案例、方案能支撑 |
| 主题通用性 | 不依赖作者账号、人设或个人经历，目标读者能直接理解和代入 |

选择总分最高的问题。总分接近时，优先选场景最具体的那个。

## 单问题硬规则

成稿只能围绕一个问题。

以下情况必须拆成多篇：

- 同时讲「能力」「关系」「产品」「客户阶段」。
- 一个正文需要 3 个以上案例才能讲完整。
- 标题像一个大课题，而不是一个具体卡点。
- 开头需要解释很多背景才能让读者看懂。

## 样例

原文材料：

```text
新人销售不能只卖产品，要学会做解决方案。客户说「发我看看」时，不要立刻回去做完整资料，要先确认客户是在了解、比价、内部汇报，还是已经有具体问题要解决。
```

拆分：

```text
[Q1] 客户说「发我看看」时，为什么新人销售一回去做资料就容易把项目做死？
[C1] 解决方案：不是 PPT，而是客户愿意继续往下走的决策路径。成稿替换成「下一步怎么推进」。风险等级：高。
[O1] 新人销售最该练的不是把资料做全，而是把客户当前最想判断的问题问准。
[E1] 客户问「你们和另一家有什么区别」，新人如果只发长技术说明，就失去二次沟通机会。
[S1] 下次客户说「发我看看」，先问他是了解、比价、汇报还是验证，再决定给一页诊断、对比表还是完整方案。
```

本次最适合成稿的是 Q1，因为它有具体对话、常见误区、机制和动作。
